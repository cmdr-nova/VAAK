# Library controller and durable Settings verification, 2026-10-10

These gates execute actual PHP implementations used by the candidate native cards. Rust still delegates mutations to PHP. They are not a claim of full Library, Search, profile, or Settings parity and do not permit cutover.

Run with real mbstring, never a replacement Unicode implementation:

```sh
api/bin/php-policy-test api/bin/library-controller-action-smoke.php /tmp/vaak-library-native-cards.json
api/bin/php-policy-test api/bin/library-settings-durable-smoke.php
```

## Boundaries

The controller harness extracts current source spans from `ap-admin.php`: POST guest/CSRF guards, RSS/Fedi interaction dispatch, bookmark folders, AJAX Bluesky interactions, poll voting, own pin/unpin/edit/delete. It imports unchanged actual auth, lookup, canonical key, durable writer, queue, signal, poll, and AS2 functions. Only the production bootstrap include is replaced with isolated declaration loading; action conditions and write logic are not replaced.

Each request is a separate PHP process against a newly provisioned disposable SQLite database. The host supplies a scalar trusted owner/actor and an established fixture session. This executes the genuine CSRF comparator and guest POST guard, but does not exercise session-cookie issuance, disabled-account login or the complete HTTP front controller.

Redis and outbound delivery/log/metrics are isolated adapters recorded against that database. RSS schema migration is a provisioned-schema adapter. Empty media fixtures and unlinked Bluesky crossposts exercise no media-object transport or real PDS writes. Delivery adapters record genuine generated AS2 Update/Delete envelopes, never contact another server. The Settings harness uses actual save/read functions with a warm disposable Redis adapter and a public-file export adapter. Empty attachment fields never make rel=me requests.

SQLite effects do not prove PostgreSQL locks, row types, concurrent writes, Redis availability, actual delivery workers or upstream PDS authorization. These are independent required gates.

## Deliberate Update/Delete privacy correction

The actual controller harness found that `ap_update_local_status` and `ap_delete_local_status` replaced valid empty stored audience arrays with public/follower defaults. For a direct note with `to=[recipient]` and `cc=[]`, this added the author’s followers to the outbound Update/Delete recipients. Both functions now preserve every valid decoded array, including `[]`; absent or malformed arrays retain the established fallback. This changes the erroneous PHP behavior deliberately, separately from Rust parity. Actual generated envelopes are asserted through the real controllers; the delivery adapter prevents federation.

## Library step 4

Bookmark folder lists, counts, empty folders, a renamed title, and a move between folders now have a Rust painter that matches the PHP list and the Bookmarks chrome. PHP still performs create, delete, and membership writes. The painter stays unused while `VAAK_LIBRARY_NATIVE_RENDER` is off. There is no folder rename endpoint; the nav prints the stored title. Soft-nav tabs omit counts and skip folder ids below 1. The full page shows `(count)` and the delete form only for the open folder.

## Library step 5

Library page windows now follow the PHP cursor. Web pages clamp offset at zero and the page size to 10–40. Mixed bookmarks stay in time order, then reference order, including a tie split across a Fediverse and Bluesky page boundary. The next offset counts source keys, so a key that paints no card is not fetched again. The full Favourites page still treats “more” as more than 20 hydrated rows before Bluesky rows are removed; soft-nav and AJAX use the filtered count. The sentinel is “Scroll for more…” or “End of Fediverse favourites”. Mastodon favourites and bookmarks read `max_id` as a status id, then `created_at` strictly older than that row, with no tie-break. `since_id` and `min_id` do not move those lists. The Link header uses the requested limit, `max_id` of the last id, and `min_id` of the first id. PHP still runs the queries. The native switch stays off.

## Library step 6

Library admission now follows the PHP privacy checks. Saved cards are refused for a guest, a deleted or tombstoned note, a muted word, a block or mute, a private or direct audience the viewer no longer holds, and a private quote nested inside a public save. An ordinary own note may keep a muted word in its own body; the same word in a quote or an Ask still hides the card. Deprioritizing an actor does not hide them. Sensitive posts with an empty warning open when that user's auto-unblur setting is on; a custom warning stays closed. Domain and alias expansion of blocks stays in the existing moderation helpers. RSS subscription refresh stays on the PHP path. PHP still decides what is saved. The native switch stays off.
