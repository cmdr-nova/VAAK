## Proposed typed contract

Use a dedicated private direct context and admitted token. Do not weaken the
existing Library/Search token constructors or expose `CardFacts` to request
JSON. The current shared Rust `render` explicitly permits authenticated
bookmarks/favourites/search only, while `facts::resolve` requires an active
database user. Guest 0 needs a distinct construction/presentation path.

| Trusted field | Meaning and acceptance |
|---|---|
| Viewer | Authenticated positive owner + current actor/key/CSRF resolved/rechecked in PostgreSQL, or explicit canonical PHP guest-profile GET/HEAD owner 0. Guest cannot construct a detail/writer context, impersonate a database user or inherit owner forms. |
| Direct surface | Profile or Detail, derived by the canonical PHP caller. The actual final PHP predicate is `focused || returnView in {status,remote_profile} || actual route view == status`. Admission must not depend solely on the action return value. |
| Card role / options | Exact `focused`, `showOpen`, `hideHeader`, lazy-media values from the canonical caller; focus class and `id=status-focus` must remain distinct from ancestor/descendant cards. No automatic focus inferred from return origin. |
| Action origin | Preserve the canonical caller's original `returnView` separately from direct admission surface. Captured origins include home/search/bookmarks/favourites and remote_profile. Validate against actual PHP controller sanitation; do not reduce allowed origins to the fixture subset. |
| Source / position | Preserve complete producer snapshots, duplicate/omitted slot identity and whole-batch cursor accounting; carry source indices before admission. No request-controlled cached roles or policy flags grant access. |
| Current facts | Current audience/source lineage, current session, actual content-block decision, saved flags/counts, avatar/emoji, current edit/poll/Ask rows and presentation settings. Presentation facts alone cannot create the admitted token. |

The token binds the final exact source tree and current facts after every
supported transformation. Root and represented/recovered quote/reblog children
must pass the exact current direct final gate: local Notes require a current
`masto_statuses` row, AT posts require a current cached row, remote AP sources
require current Create/Update/Delete/Tombstone or legacy Quote-only lineage,
otherwise a current undeleted mention. A known Create/Update lineage takes
precedence over Quote/QuotePost interaction rows on the same URI. Normal Undo
of a quote/boost must not withdraw the original Note; actual deletion must.
Fragments/trailing slash aliases and the depth-16 bound remain explicit.

Current public/unlisted/author/follower/recipient semantics come from actual
`ap_visibility_status_audience_allowed`; grant withdrawal is checked at the
last paint boundary. Compact quote preview bodies need retained original-source
authority. State-only harmless pending descriptors may paint pending chrome;
they cannot authorize recovered body text/media. Owner-bound RSS preview access
is separate evidence, not generic public AP permission.

Explicit-open root blocks use actual `ap_actor_is_content_blocked`, at the
canonical caller boundary. Personal mute, muted words, server `kind=mute` and
indexable/discoverable withdrawal do not suppress explicitly opened permitted
content. Do not apply `hidden::status_hidden_on_profile` or Library's recursive
word/mute filter as the direct contract. Nested block/quote behavior must follow
the actual caller and quote helper, not an invented blanket recursive rule.

while its budget differs. Classification is not audience proof.
