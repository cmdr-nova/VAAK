# Search PHP presentation bridge checkpoint, 10.10

The default-off PHP bridge now calls the separate authenticated `/internal/search/render` endpoint. No feature flag was enabled, and nothing was committed or deployed. The original PHP collector, ranking, cache, resolver, summary, headers and action writers remain the production orchestration.

`api/ap-search-native.php` uses `VAAK_SEARCH_NATIVE_RENDER=1`, a separate `VAAK_SEARCH_NATIVE_SECRET` of at least 32 bytes, and optional `VAAK_SEARCH_NATIVE_URL` (default `http://127.0.0.1:8787/internal/search/render`). Only exact HTTP loopback hosts `127.0.0.1` and `[::1]` and the exact endpoint path are accepted; credentials, queries, fragments, redirects and proxies are excluded. Transport limits are 200 ms connect, 3 seconds total, 2 MiB request and 8 MiB response.

The envelope supplies current canonical authenticated owner, CSRF, Bsky availability, three ordered source arrays, and recursive current-owner Bsky bookmark tuples. Browser request parameters supply none of those permission or session facts. Search view and media behavior are fixed in the native Search session. Each source section is capped at 40. Original arrays are strictly JSON-encoded before cache-only source assembly; invalid UTF-8 and recursive/unserializable source values fall back without substitution. Assembly preserves already-complete supplied quote/reblog trees and original rows for PHP fallback. A quote URL or raw QT target without a complete supplied `quote.quoted_status` triggers whole-batch fallback **before any lookup or native request**: canonical PHP late recovery can consume a preview budget even for a cache hit, so early native assembly would change that observable orchestration. Unsupported or incomplete source normalization remains an explicit whole-batch native fallback; this checkpoint does not claim native source IO parity.

`admin_search_render_sections` attempts one batch for its selected section windows, before painting any cards. `admin_search_page_fragment` attempts one batch for its single section after the existing collector. PHP keeps headings, list and fragment wrappers, summary counts, has-more and raw source offsets. A denied native status may yield successful empty HTML while its raw cursor advances. Malformed source rows trigger compatibility fallback to the original PHP loops; no source rows are silently filtered to fit the bridge.

A response must have exactly `ok`, `source_counts`, `accounts`, `hashtags`, `statuses`; counts must be integer-equal to the supplied original windows. Accounts and tags require exact ordered string slots. Status slots contain only `source_index` and `html`, with strictly increasing unique nonnegative indices inside the original status window. Every section is validated and buffered before any native HTML is emitted. A late status failure discards earlier native account/tag output and paints the complete original batch in PHP.
