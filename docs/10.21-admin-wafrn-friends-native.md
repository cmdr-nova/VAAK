# Admin Wafrn friends native read (step A4)

Rust paints the Wafrn friends page (`?view=friend_servers`): the "Default Wafrn instances" list, the add form and the admin override rows with their Remove forms. PHP keeps the shell, the session, the admin gate and both mutations (`wafrn_friend_add`, `wafrn_friend_remove`).

Admin only. Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` plus `VAAK_ADMIN_FRIEND_SERVERS_NATIVE=1`, in both `www.conf` and `vaak.env`.

## One source for the default list

PHP-FPM and the worker read different env files, so `VAAK_WAFRN_FRIEND_HOSTS` could differ between them. The native page therefore runs only while that variable is unset or blank on both sides: the PHP bridge skips the call when PHP sees it, and the worker refuses when it sees it. With it unset, both read the same catalog file:

1. `/var/lib/mkultra/ap/wafrn-friend-hosts.txt` (written by `ap-wafrn-friend-refresh.php`),
2. else `deploy/wafrn-friend-hosts.txt` under the API root (`VAAK_API_ROOT` for the worker),
3. else `waffles.baeddel.social`.

Tokens split on commas and ASCII whitespace, as `preg_split('/[,\s]+/')` does. Rust accepts only plain hostnames (letters, digits, hyphens, dot-separated labels of 1 to 63 bytes), optionally with `https://` and one trailing slash; it lowercases, drops `mkultra.monster`, dedupes and sorts by bytes like `sort(SORT_STRING)`. Any other token (a scheme other than https, a port, a path, an empty label, a trailing dot, an underscore, non-ASCII) renders the PHP page instead, because `parse_url` and `FILTER_VALIDATE_DOMAIN` read those in ways not worth porting. The refresh script only writes validated hostnames, so the production catalog stays native.

A catalog path that exists but cannot be read or stat'ed (permissions, invalid UTF-8, over 1 MiB, over 2000 hosts) is also a PHP fallback, never an empty list. One gap remains: if the worker can read the runtime catalog but PHP-FPM's user cannot, PHP would have fallen back to the bundled file or the one-host default while Rust shows the catalog.

## Overrides

`SELECT host, note, updated_at FROM ap_wafrn_friend_servers WHERE enabled=1 ORDER BY host`, at most 100 rows (101 renders PHP). A missing table lists no overrides, as PHP's swallowed exception does. Reply rows are `{host, note, updated_at}`; the bridge rejects other keys, non-string values and duplicate hosts.

## Parity check

`api/bin/admin-wafrn-friends-native-review.php` (sandbox only; it writes the runtime catalog path and refuses if one already exists) renders the genuine branch of `ap-admin.php` with its bundled path pointed at the worker's API root, and compares whitespace-collapsed HTML in full and shell modes. Scenarios: no files and no table, an empty table, a production-like catalog that wins over the bundled one, mixed separators (CRLF, tabs, vertical tab, form feed, commas, blank lines, upper case, `https://` with a slash, `mkultra.monster` in two cases, duplicates), an empty and a blank catalog, bundled only, and override rows with HTML in hosts and notes, a disabled row and a `0` note. The real bridge validator must accept each reply and reject an int note, an extra key, a duplicate host and an extra binding. Fallbacks: nine odd tokens, ordinary, disabled and revoked admins, a wrong token, a nonzero offset, a filter selector and 101 overrides.
