## Canonical surface differences to preserve

Direct remote profiles use `ap_actor_is_content_blocked`: personal mutes, muted phrases and server `kind=mute` do **not** prohibit opening that profile. Personal/server blocks do. Library uses the stronger recursive status policy, including personal mutes and phrases; Search's canonical actor/status filter applies personal/server actor moderation, while its actor-only helper does not itself match body phrases. These differences are PHP behavior and must not be erased by sharing Library's hidden sets wholesale with direct profiles.

Mute preferences hide selected application surfaces; they do not revoke ordinary ActivityPub public access. The direct-profile check here is the actual content-block predicate used by the page, not full page HTML rendering or a complete route test.
