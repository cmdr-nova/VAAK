# Admin Queue health native read (step A8, second part)

Rust paints the two database tables on the Queue health page (`?view=queue_health`): Queue classes (queued, active, failed and attempt counts plus the five age columns for each of the six durable queues) and Federation delivery dependencies (the 25 most recently updated parent activities with their per-inbox child deliveries). PHP keeps the shell, the session, the admin gate and everything it measures itself: the readiness checks, Redis counters, path timings and slow routes. PHP also keeps the totals grid, which it now fills from the reply rows.

Admin only. Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` plus `VAAK_ADMIN_QUEUE_HEALTH_NATIVE=1`, in both `www.conf` and `vaak.env`. When the native body arrives, PHP skips its six queue queries and the dependency query.

## What it does

`ap_admin_native_read_body('queue_health', 0, null, $rows)` posts the usual admin envelope with offset 0 and no selectors. The worker requires a current active administrator before and after a READ ONLY transaction and copies the PHP `$queueDefs` list:

- A queue whose table does not exist (`to_regclass` is NULL) is PHP's "unavailable" row with zero counts.
- Each other queue runs the PHP aggregate: state counts, `SUM(attempts)`, oldest active claim, oldest open item, next due, last success and oldest failure, as trimmed text for `relative()`.
- Dependencies group `ap_fanout_delivery_queue` by `activity_key`, newest update first. Both PHP and Rust now break ties on the latest update by activity key; before, PHP left them in plan order, including which rows made the 25-row cut.

Rows are `{name, ok, queued, active, failed, retries}` for exactly the six queues in PHP's order. The bridge validator rejects any other name or order, non-int or negative counts, and nonzero counts on an unavailable row. `ap_admin_native_read_body` now hands validated reply rows back by reference, so the page's totals grid sums the same numbers the tables show.

Renders the PHP sections instead when: any query other than the table check fails (PHP shows that queue as unavailable or drops the dependency card), a date is in a format `relative()` is not proven on, printed text matches the `ap_fix_utf8` mojibake pattern that `h()` would repair, or the session is not a current active administrator.

## Parity check

`api/bin/admin-queue-health-native-review.php` (sandbox only) runs the genuine data block and template regions with the genuine helpers and compares whitespace-collapsed HTML for the Queue classes and dependency cards, and checks the totals grid built from the reply rows equals PHP's. The fixture has every queue state, TIMESTAMPTZ and text date columns, NULL due times falling back to created times, escaped activity keys, 28 activities with update-time ties around the 25-row cut, empty queues, and missing queue tables (including the fan-out table, which drops the dependency card). The real bridge validator must accept each reply and reject a renamed queue, a five-queue list, a string count and counts on an unavailable row. Fallbacks: a queue table without an `attempts` column (PHP's per-queue catch), a date only `strtotime` reads, mojibake text, ordinary and unknown accounts, and a nonzero offset.
