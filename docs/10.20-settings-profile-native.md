# Settings profile form native read (step S1)

Rust paints the profile form on the Settings page (`?view=profile`): the preview card, display name, email, accent picker, bio, forum signature, badges, avatar and header fields, the 8 profile field rows with their verified marks, reply and quote policies, the profile and Home toggles, and the help notes. PHP keeps the shell, the session, CSRF injection (the page script adds the token to the form on submit, as before), the uploads, the save itself and every other section on the page.

This is a personal form. Every account can use it, so the worker admits any active account and never checks for admin, the same way as `10.19-settings-lists-native.md`. It reads only the session owner's `ap_users` row and their `actor_profile` row.

Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` plus `VAAK_SETTINGS_PROFILE_NATIVE=1`, in both `www.conf` and `vaak.env`. It is separate from the other Settings flags, so it can be turned off alone.

## What it does

`ap_settings_native_body('settings_profile', $viewerAdmin)` posts the usual envelope with offset 0 and `viewer_admin`. The worker requires the owner to exist, not be disabled and have exactly that admin role, before and after a READ ONLY transaction.

- Identity: actor key (default `cmdr_nova`), actor id (default `https://mkultra.monster/users/<key>`, trailing slash trimmed), username (trimmed, falling back to the key) and email, as the top of `ap-admin.php` builds them.
- Profile: the Redis profile cache `vaak:profile:v1:<sha256(trim key)>` when PHP would accept it (an object with non-null actor_key, name and summary and a boolean trending_enabled), otherwise the `actor_profile` row through the `ap_profile_get` row rules, including the defaults for columns an old schema lacks. A NULL or missing policy column is an empty string there, as in PHP, so no option is preselected. The worker never writes the cache.
- Bio: kept as is when it has rich tags, otherwise the same br/p replacements, `strip_tags`, `html_entity_decode`, trim and blank-line collapse as the template.
- Badges: `ap_profile_normalize_badges(..., false, false)` (the existing `normalize_selected_badges(.., false)`), so Admin and Supporter never show as choices.

Rows are one `{actor_key, source}` entry, where source is `cache` or `db`. The bridge accepts exactly one such row, checks the request binding including `viewer_admin`, then rechecks that the session user and their admin role are unchanged.

Renders the PHP form instead when: there is no `actor_profile` row (PHP shows defaults), any printed text matches the `ap_fix_utf8` mojibake pattern (both `ap_profile_get` and `h()` would repair it), the attachments are not a JSON list of objects, the badges are a JSON object, the bio or a field value needs `strip_tags` or `html_entity_decode` behaviour outside the proven subset (comments, `<3`, unclosed or escaped-quote tags, HTML5-only named entities such as `&hellip;`, control or noncharacter references), a value is a type PHP would cast oddly, updated_at is a date the helper can't parse, the account is unknown or disabled, its admin role changed, the session owner differs from the page owner, or anything else in the bridge refuses.

## Parity check

`api/bin/settings-profile-native-review.php` (sandbox only) renders the genuine form region and its `$atts` / `$summaryForForm` preamble with the genuine `ap_profile_get`, `ap_fix_utf8`, badge, avatar, `h` and `relative_time` helpers and the genuine identity block, and compares whitespace-collapsed HTML for an admin, an ordinary account with no username, actor id or email, and an account whose username is blank, in full and shell modes. Textarea contents and every `value="..."` attribute are also compared exactly, since their whitespace is saved back. It runs on the current schema and on an old schema missing five columns. With a shared cache Redis (`port/db` argument) it also checks a valid cache entry wins over the row, that invalid entries (non-boolean trending, null summary, a list, garbage) fall back to the row on both sides, and that PHP writes the cache only on a miss. The real bridge validator must accept each reply and reject an extra row key, an unknown source, two rows and a flipped role binding. Fallbacks: every case listed above, plus missing role and nonzero offset.
