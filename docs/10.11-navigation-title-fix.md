# RSS-to-Home navigation title repair

The reported bug was that returning Home from RSS left the tab titled “VAAK · RSS.” The unread-notification polling code captured the original page’s title and notification/DM view flags. Soft navigation installed a new view, but a later unread poll reused that original title.

The repair keeps those values aligned with the currently installed view. The shared title lifecycle retains the latest unread notification and DM counts, derives labels from the canonical PHP `view_title()` mapping, and updates the title when timelines, installed main views or profiles change. Polling renders against that current title. Notifications and DMs suppress their own unread prefix while preserving counts for subsequent navigation. The polling intervals are unchanged.

Implementation: [title lifecycle and unread rendering](../api/ap-admin.php) (`vaakSetCurrentViewTitle`, `renderCurrentInboxTitle`); its three installation hooks cover timeline navigation, main-view installation and remote-profile installation. The current lifecycle, unread code and hooks remain byte-identical to the accepted frozen controller SHA256 `d3aac2a61be0972ab4b545c25e5258dd5003bb174b1de89aa61b3e43a3bc704b`. Comparing that controller with the current file shows only separately owned Library changes; no title/navigation drift.

Independent acceptance recorded **44 title checks: 33 actual HTTP/SAPI checks and 11 browser/controller checks**. Actual RSS document → marked soft Home link retained the document and canonical Home title through genuine notification polling. Canonical full RSS navigation, Back/Forward and queued Home→Local navigation ended with matching installed views and titles. Genuine isolated SQL notification/DM rows drove endpoint unread prefixes. The later Notifications/DM suppression and retained-count controls invoked the actual lifecycle setter; those controls prove renderer behavior, not complete Notifications/DM route parity.

Evidence: [independent review](../rust/target/parity-evidence/post-detail-in-place/repair/independent-review/REVIEW.md), [proof index](../rust/target/parity-evidence/post-detail-in-place/repair/independent-review/proof-index.json), and the adjacent `titles/` receipts. Evidence is retained locally under ignored `rust/target`; it is not shipped to the website.

This repair is local, uncommitted and undeployed. It does not claim native Rust post-detail parity or complete VAAK parity.
