# Settings muted words native actions (step S7a)

Rust runs the two muted-word actions from Settings > Profile: `muted_word_add` and `muted_word_remove`. PHP keeps the session, CSRF, the notice text and the page.

Personal, never admin-gated: any active account can use it. Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` (the shared loopback token) plus `VAAK_SETTINGS_MUTED_WORDS_ACTIONS_NATIVE=1`, in both `www.conf` and `vaak.env`.

## Route

`ap_settings_action_native()` in `ap-admin-native.php` posts `{protocol_version:1, owner_id, actor_key, action, fields}` to `/internal/settings/action`. It only calls when the session user is the owner the page acts for, with the same actor key. The worker holds that account's row (`FOR SHARE`, active, same actor key) for the write. The reply is `{protocol_version, ok, outcome, phrase, id, php_cache, request_binding}`; the bridge turns it into the exact array `ap_muted_word_add` or `ap_muted_word_remove` returns, so the handler's notice and error strings are unchanged. Any non-200 answer, or a reply that breaks the closed shape, runs the PHP helper instead.

## What it copies

- **Add:** `trim(preg_replace('/\s+/u', ' ', $phrase))`, the trimmed note, the 2 to 200 character and 300 character limits (in that order), the case-insensitive duplicate check against the owner's phrases newest first, then the insert with `gmdate('c')`.
- **Remove:** `id < 1` is "Missing phrase id."; otherwise the owner-scoped delete, and "Phrase not found." when nothing matched.
- **Caches, after the commit:** `ap_muted_words_cache_clear($owner)` (the cached phrase list is stored again, freshly read, with the `VAAK_REDIS_RELSET_TTL` TTL; the owner's fragment keys go; the owner's trends epoch is bumped) and the handler's `admin_tl_cache_clear()` (ranked and owner-index keys, every `tl_*.json`). A duplicate add only runs the global clear, and a not-found remove only the owner clear, which PHP does itself, as before.

After the commit nothing answers 422. Cache work the worker could not do (Redis off or failing, the timeline cache directory missing, a cached phrase with U+2028 or U+2029, which `json_encode` escapes) comes back in `php_cache` and the bridge and handler run it in PHP. Every step is idempotent.

## Left to PHP

A phrase or note with NUL, a phrase with U+180E, any phrase (new or already stored for the owner) with a character whose lowercase PHP 8.3 might map differently (a multi-character mapping such as U+0130, or capital sigma with its final-form rule), an id past int4 on an INTEGER table, and a disabled account.

## Parity check

`api/bin/settings-muted-words-actions-native-review.php` (sandbox only) runs the genuine handlers and helpers, then the native branch, against PostgreSQL, Redis and a scratch cache directory, comparing the notice, error, view, every row, every Redis key with its TTL presence and every cache file. Scenarios cover new phrases with collapsed whitespace and a note, empty and whitespace notes, duplicates by case and accents, emoji, another account's phrase, every length limit, removes of own, foreign, missing, zero, junk and negative ids, a stored phrase with a line separator, the fallbacks above, a missing cache directory (PHP redoes the clear), and the bridge validator.
