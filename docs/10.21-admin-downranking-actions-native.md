# Admin downranking actions native (step A10a)

The worker runs the four Home downranking vocabulary actions: `downrank_term_add`, `downrank_term_delete`, `downrank_signal_clear` and `downrank_term_preview`. PHP keeps the session, CSRF, the admin-only gate, the notice and error text, and the page.

Admin only. Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` plus `VAAK_ADMIN_DOWNRANKING_ACTIONS_NATIVE=1`, in both `www.conf` and `vaak.env`. With the switch off in either place PHP runs the actions as before.

## What it does

After PHP's admin gate, `ap-admin.php` hands the raw form values to `ap_admin_action_native` (`ap-admin-native.php`), which refuses anything the form never sends (an array, a missing field, a session that is not an admin), then posts `{protocol_version, owner_id, actor_key, action, fields}` to `/internal/admin/action` with the loopback token.

Every write runs in one transaction that first reads the acting account `FOR SHARE`: it must still be an active admin with the actor key PHP sent, so a ban or demotion cannot interleave. Then, copied from the handlers:

- add: the phrase squashed (`preg_replace('/\s+/u', ' ')` and `trim`), 2 to 120 characters; the category reduced to `[a-z0-9_-]` and kept only when it is `protected_class`, `sexualized_harassment` or `custom`; the same `INSERT … ON CONFLICT (phrase) DO UPDATE` that re-enables an existing phrase.
- remove: the old phrase and category read, the row deleted, the audit written even when no row existed, as PHP does.
- clear signal: the actor trimmed and stripped of trailing slashes, every owner's `ap_home_suppression` row for it deleted, then the server trends epoch bumped (`INCR` plus 30 day expiry) after the commit. If Redis is unreachable the reply asks PHP to bump it.
- preview: the last 2000 public or unlisted `Create` events from the past 30 days, their summary and content through a copy of `strip_tags` and `ap_downrank_phrase_matches_text` (whole token, caseless, hashtags ignored), counted with the first eight samples.

Each action writes its `ap_home_downrank_audit` row (`term_saved`, `term_removed`, `signal_cleared`, `term_previewed`) with PHP's `details_json`. PHP writes that row as a separate statement and only logs a failure; here it shares the transaction, so a failed audit rolls the action back and PHP runs it instead.

The reply is `{protocol_version, ok, outcome, preview, php_epoch_bump, request_binding}`. The outcome is a closed word per action (`term_saved`/`bad_phrase`, `term_removed`/`invalid_term`, `signal_cleared`/`missing_actor`, `previewed`/`bad_preview_phrase`) that PHP turns into its usual notice or error. The bridge rejects any other key or outcome, a binding for another account or action, a preview on another action, a preview over eight samples or past its count, and an epoch bump on anything but a cleared signal.

The preview query now also orders by `id DESC` after `created_at DESC`, on both sides, so rows with the same time come back in one order.

Runs in PHP instead (the worker answers 422 before any write) when: the phrase holds a NUL or U+180E (PCRE2's `\s` and Rust's differ there), PHP's 120 or 2048 byte audit cut would land inside a character (PHP's audit insert then fails quietly), a term id is past int4 on an INTEGER table (PHP's query raises), cached post text holds U+180E, the account is not an active admin with that actor key, or any query fails.

## Parity check

`api/bin/admin-downranking-actions-native-review.php` (sandbox only) runs the genuine handler chain from `ap-admin.php`, with the genuine `admin_home_downrank_audit`, `ap_downrank_phrase_matches_text` and `ap_trends_policy_epoch_bump`, against a seeded PostgreSQL fixture and a Redis database. For each scenario it runs PHP with the switch off, reseeds, runs the native branch with PHP's handlers disabled, and compares the notice, error, view, preview, every row of the vocabulary, audit and suppression tables, and the server and owner trends epochs. Fallback cases must reach PHP with nothing written. It also checks the bridge validator and that the worker refuses a forged actor key and an unknown field. Run the worker with `VAAK_ADMIN_DOWNRANKING_ACTIONS_NATIVE=1` and the harness's Redis (`DOWNRANK_ACTIONS_REDIS`, default `redis://127.0.0.1:6390/5`) as `VAAK_REDIS_URL`.

Scenarios cover new, existing, oddly categorised, Unicode-spaced, HTML-holding, 120 and 121 character and empty phrases, removing present, missing, invalid and zero ids, clearing a signal held by two owners, an unknown and an empty actor, and previews that are caseless, tagged, Unicode, hashtag-only, matchless, one character, tags only, empty and too long, over posts with tags, comments, followers-only, non-Create, rejected and month-old rows.

2026-10-21: 120/120 checks with INTEGER ids and 121/121 with BIGINT ids.
