# Settings OAuth token revoke native action (step S7c, first part)

Rust runs `revoke_oauth_token` from Settings > Security through the personal `/internal/settings/action` route (see `10.21-settings-muted-words-actions-native.md`). PHP keeps the session, CSRF, the notice and the page. Personal, never admin-gated. Default off: it needs `VAAK_ADMIN_READ_NATIVE=1`, `VAAK_ADMIN_READ_SECRET` and `VAAK_SETTINGS_TOKENS_ACTIONS_NATIVE=1`, in both `www.conf` and `vaak.env`.

It copies `ap_oauth_token_revoke_by_id` with the owner's scope: a non-positive id is refused before any query (the handler's `$tid > 0`); otherwise `revoked_at = gmdate('c')` on the token when it is still active and belongs to the account. The cmdr_nova account (`ap_db_cmdr_nova_user_id`: that row's id, else 1) also owns legacy tokens with no `user_id`. Nothing is cached for tokens, so there is no cache work.

Left to PHP: two `cmdr_nova` rows (PHP's unordered `LIMIT 1`), a token id past int4 on an INTEGER table, and a disabled account.

## Parity check

`api/bin/settings-tokens-actions-native-review.php` (sandbox only) runs the genuine handler and helper, then the native branch, and compares the notice, error, view and every token row: own, already revoked, another account's, legacy tokens as an ordinary account and as cmdr_nova, missing, zero, junk, negative and absent ids, no cmdr_nova row, the fallbacks above, and the bridge validator.

2026-10-21: 54/54 checks with INTEGER ids and 55/55 with BIGINT ids.
