# Admin Home downranking native read (step A9, first part)

Rust paints the phrase list on the Home downranking admin page (`?view=downranking`): each admin-managed phrase with its category tag, its added time and its Remove form. PHP keeps the shell, the session, the admin gate, the intro text, the add and preview forms, the preview result and every vocabulary action (add, remove, preview).

Admin only. Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` plus `VAAK_ADMIN_DOWNRANKING_NATIVE=1`, in both `www.conf` and `vaak.env`. When the native body arrives, PHP skips its vocabulary query.

## What it does

`ap_admin_native_read_body('downranking')` posts the usual admin envelope with offset 0 and no selectors. The worker requires a current active administrator before and after a READ ONLY transaction and runs PHP's query, `ORDER BY category ASC, phrase ASC`. `phrase` is UNIQUE, so that order is total and both sides read it from the same database collation. The Remove form carries the session CSRF token from the envelope.

Rows are `{id}` for at most 1000 phrases. The bridge validator rejects any other key, a non-positive or non-int id, and a repeated id.

Renders the PHP list instead when: the table is missing (PHP shows its migration notice), a `created_at` is in a format `relative_time` is not proven on, printed text matches the `ap_fix_utf8` mojibake pattern that `h()` would repair, there are more than 1000 phrases, or the session is not a current active administrator.

## Parity check

`api/bin/admin-downranking-native-review.php` (sandbox only) runs the genuine vocabulary query and phrase list template with the genuine `relative_time` and `h`, and compares whitespace-collapsed HTML in full and shell modes. The fixture has HTML and quote characters in a phrase and a category, mixed-case phrases, emoji and accented text, a disabled phrase (PHP lists it too), a future time, a zoneless time, and an empty table. Fallbacks: every case listed above, plus ordinary, disabled-admin and unknown accounts, a nonzero offset and a filter selector.

2026-10-21: 33/33 checks with INTEGER ids and 33/33 with BIGINT ids.

# Admin Downranked native read (step A9, second part)

Rust paints the Downranked review page (`?view=downranked`) below its intro and search form: the grouped signal list with names, categories, score, viewers, expiry, up to five evidence links per actor, the Open profile, Clear signal, Server mute and Server block controls, the pager script, and the Recent audit trail. PHP keeps the shell, the session, the admin gate, the search filter, CSRF, and every clear, mute and block action.

Admin only. Default off. It needs `VAAK_ADMIN_DOWNRANKED_NATIVE=1` as well as the admin read switches, in both `www.conf` and `vaak.env`.

## What it does

PHP runs its stale-signal cleanup (the `DELETE` of expired and local rows in `admin_home_downrank_purge_stale`) first, then asks for the native body only when there is no search query; a search always renders PHP. The worker requires a current active administrator before and after a READ ONLY transaction and copies:

- `admin_home_downranked_actor_rows`: signals grouped by trimmed actor, exempt and expired rows skipped, max score, viewer count, latest expiry with its last object, categories merged in order. Both PHP and Rust now order by `suppressed_until DESC, score DESC, actor_id ASC, owner_user_id ASC`; before, ties left the grouped order and category order to the plan.
- `admin_home_downrank_evidence_rows` and `ap_downrank_text_categories`: the latest 100 public or unlisted events per actor (now `created_at DESC, id DESC` in both), the three built-in patterns with PCRE's ASCII word boundaries and whitespace, enabled admin phrases as whole Unicode tokens matched caselessly with hashtags blanked, and the last-signal-object rule.
- `actor_display_name` and `admin_remote_actor_href` through the same cached actor label and warm the Blocks page uses, `admin_status_href(…, 'downranked')`, and the 50 latest audit entries (`created_at DESC, id DESC`).

Rows are `{actor_id, viewers, evidence}` for at most 300 actors. The bridge validator rejects any other key, a repeated or non-https actor, fewer than one viewer, and more than five evidence links.

Renders the PHP page instead when: a summary or phrase contains `<` or NUL (PHP's `strip_tags` would change it) or U+180E (PCRE2's `\s` and Unicode White_Space differ there), a `suppressed_until` is in a format `strtotime` handles but the copy is not proven on, an actor is not an https URL, is on a local host, or is a Bridgy Bluesky or Threads actor (PHP builds their profile links from other helpers), a category list holds non-strings or is keyed, an evidence object is an AT URI, printed text matches the mojibake pattern, there are more than 300 actors or 20000 signals, or the session is not a current active administrator.

## Parity check

`api/bin/admin-downranked-native-review.php` (sandbox only) renders the genuine branch twice, once with the bridge off and once with it returning a marker, puts the native body in place of the marker and compares whitespace-collapsed HTML with the PHP page, in full and shell modes. The fixture has one actor across three viewers including a trailing-slash form, negative and tied scores, merged and filtered categories, invalid category JSON, exempt local and cmdr_nova actors, an expired signal, a signal expiring in under a minute, more than five matches, spoiler-only evidence, private events, an announce suffix, a 140-character cut through emoji and accents, U+3000 whitespace, `ñslop`, a hashtag hit on a built-in pattern, a caseless accented admin phrase, a phrase with a doubled space, a Bluesky profile actor, an uncached actor and audit entries with empty, `0` and tied fields. The real bridge validator must accept each reply and reject the cases above. Fallbacks: every case listed above, plus ordinary, disabled-admin and unknown accounts, a nonzero offset and a search selector.

2026-10-21: 57/57 checks with INTEGER ids and 57/57 with BIGINT ids.
