## Confirmed timestamp defect

The deployed OpenSim PHP runtime defaults to UTC. Its PDO factory does not set a SQL timezone, while MariaDB uses SYSTEM/CEST. Player `last_decay_at` is TIMESTAMP: SQL returned `2026-10-10 17:35:06`, absolute epoch 1791646506. A read-only connection-local `SET SESSION time_zone='+00:00'` returned `2026-10-10 15:35:06` with identical epoch and elapsed seconds (82130 at that probe). PHP parses the timezone-free 17:35 value as UTC, delaying decay by two hours in summer (one in winter). This is a clock contract defect, not a passive resonance grant.

PHP mirror writes the naive bridge timestamp into PostgreSQL TIMESTAMPTZ using the database session timezone. Rust `parse_bridge_time` treats the same naive string as UTC. The live VAAK origin row consequently had last_checkin 17:35+02 but last_decay 19:35+02. Linked VAAK rows intentionally skip local decay; OpenSim remains authoritative. The staged upstream patch sets only the API connection to UTC and emits explicit UTC `last_decay_at` for bridge responses, avoiding historical-row rewrites or guessed local timezone conversion inside VAAK.
