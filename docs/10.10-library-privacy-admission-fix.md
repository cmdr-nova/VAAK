# Deliberate Library privacy repair (2026-10-10)

This repair changes canonical PHP behavior deliberately before Rust parity comparisons. Saving an item never grants permanent permission to read it. The isolated ingress proof found that current audience SQL rejected a revoked follower, deleted local note and denied nested quote while Library still dispatched those cached statuses to its painter.

PHP now checks current durable audiences and recursive moderation after enrichment, after Bluesky normalization, and after the shared painter's late quote recovery, before output. Accessible saved private/direct/unlisted posts retain their existing behavior. Synthetic interaction IDs and flags, action handlers/CSRF/URLs and raw pagination cursors are retained. RSS resolves the current owner's actual row and never falls back to an unscoped or stale saved snapshot; it is not checked as an AS2 post.

Personal mutes and muted words now also suppress Library cards, including CWs and nested quotes. This is an intentional tightening from the previous Library behavior: saves and folder memberships remain stored and return after unmuting. Direct profile/post personal-mute exceptions are unchanged. Native Bluesky admission checks current owner-scoped `bsky_hide_dids`, author/profile aliases, repost and quoted authors and nested words. Old owner blocking/muted AppView flags cannot override a current unmute/unblock; remote blockedBy evidence remains restricted. Sensitive labels still use the existing CW/unblur rendering settings instead of hiding the whole post.

Legacy PHP/Redis raw HTML reads and the legacy Rust `/shadow/library-fragment` hit are refused because raw HTML contains no policy manifest to revalidate. PHP uses existing structured row/cache hydration and renders again. Old HTML cache writers remain harmless pending cleanup; this deliberately gives up their fast hit path until a current policy manifest/native admitted-card path exists.

Validation: `api/bin/library-privacy-admission-smoke.php` executes actual PHP audience SQL, Library admission helpers, RSS lookup, native DID table query, domain and Unicode muted-word helpers against isolated SQLite. Its painters, migration calls and cached-set transport are fixtures, so it establishes admission rather than full HTML/action parity. 61 cases pass, including late hydrated revoked/deleted quotes. Existing privacy moderation smoke passes 30 checks; audience source smoke passes 8. Rust's handler test checks all four raw Library cache kinds return 404 before any store can be accessed. The projection client requires a configured isolated Rust URL and was not executed in this subtask. No deployment, commit, version bump or Rust native-card cutover is part of this repair.


Fresh review extended the final gate to keep compact Bluesky previews bound to full request-local native PostViews. The returned preview JSON does not include policy objects. Current DID moderation, remote blockedBy, nested quoted authors, and sensitive labels survive preview-to-options conversion. Flat no-cache quote URLs receive target host/subdomain moderation. RSS mirror enrichment is explicitly owner-scoped; an `is_rss` flag alone cannot bypass current row ownership or durable mirror audiences. Another owner's public AS2 mirror body remains readable without private subscription enrichment.

The host PHP CLI lacks mbstring. Earlier denial-only phrase cases could pass due to the missing function caught by admission; those results were insufficient. The updated fixture explicitly requires real mbstring and checks allowed/denied/restored pairs. A matching package was downloaded and extracted under `/tmp/vaak-php-mbstring-test`, without a system installation. Run `api/bin/php-policy-test api/bin/library-privacy-admission-smoke.php`, or export `PHPRC=/tmp/vaak-policy-php.ini` for spawned PHP fixtures (the normal PDO SQLite config scan remains enabled). These temporary runtime files are not repository artifacts; on other machines use installed mbstring or set `VAAK_TEST_MBSTRING_EXTENSION` to a compatible real extension.


The final alias regression retains full ActivityPub quote policy evidence under every canonical URI, web URL, fallback reference and final emitted options URL. Both registration and final lookup use the same trim/fragment/trailing-slash normalization. Actual converter controls confirm private and blocked authors remain denied when the durable/cache lookup misses, while public source and normalized aliases remain allowed. The independent distinct-URI/web-URL reproduction now reports both actual source admission and compact options admission as false.
