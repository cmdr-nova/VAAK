# Search continuation repair and browser gate

Actual canonical PHP Search fragments exposed a continuation bug: ten consumed sources were denied at the final painter, returning zero articles, offset 10 and `has_more=true`; the following fragment contained two valid cards and offset 12. `window.vaakBootSearch` previously treated every zero-article reply as the end, losing those later results.

The change is confined to that Search boot function in `api/ap-admin.php`. An empty fragment consumes its explicit cursor only when it is a decimal safe integer strictly greater than the requested offset. It then honors the fragment's continuation metadata with the existing `X-Has-More` fallback. Missing, malformed, unsafe, unchanged or retreating empty cursors stop with the existing offset retained. Ordinary nonempty appends, fold enhancement, authenticated request options, error handling and login redirects retain their existing behavior.

`api/bin/search-loader-browser-fixture.py` extracts the verbatim boot IIFE and uses the actual canonical exported fragments from `search-cache-privacy-independent.php`. It models only HTTP responses and IntersectionObserver visibility notifications. The lightweight list shell is synthetic; parsing, loading skeleton, busy state, insertion, source cursor updates and sentinel state execute actual browser JavaScript. It does not prove authenticated endpoint routing, network delivery, whole Search soft navigation or typed native admission.

Candidate and before pages are `/tmp/vaak-search-loader-browser.html` and `/tmp/vaak-search-loader-before.html`. The before source is obtained from `git show HEAD:api/ap-admin.php`; the fixture's baseline expectation requires reproducing the exact premature stop, not merely running candidate logic twice. Root Cua executed both pages in the actual in-app browser: candidate **PASS 46 actual Search boot controls**; HEAD **REPRO PASS 22**, explicitly observing that the empty server offset-10/has-more page incorrectly stopped at local offset 0.

Controls cover the canonical empty advanced page followed by two distinct actual cards; explicit server end versus header precedence; section/query/resolve/limit and `same-origin`/`no-store` request preservation; unchanged, missing, negative, retreating, partially numeric and unsafe cursors; absence of optimistic append on errors; existing 401/`X-VAAK-Auth` redirects; overlapping fetch suppression; detached-list suppression; and bootstrap binding. Accounts/hashtags checks exercise generic section forwarding with synthetic empty metadata, not their respective painter features.

PHP syntax and diff whitespace checks pass. No production calls, commit, activation or deployment occurred.
