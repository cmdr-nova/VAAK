# Privacy parity discovery — Library, Search, profiles and post detail

Date: 2026-10-10. Read-only source audit; no implementation or production changes. Anchors describe current source and may move. These cases are acceptance prerequisites, not a declaration of parity.

## Canonical boundaries and reuse hazards

- `api/ap-db.php:11278` (`ap_row_is_hidden`): server blocks, global mutes, personal mutes and blocks. `:11300` (`ap_actor_is_content_blocked`) deliberately excludes personal mute on directly opened profiles/posts. Do not use a timeline filter to erase that direct-view behavior.
- Domain blocks and global mutes include subdomains (`ap_user_is_blocked`, `:10963`; `ap_is_globally_muted_actor`, `:9014`). `rust/vaak-worker/src/hidden.rs:43` uses exact domain membership only. Its host parser accepts only lowercase `https://`; its alias expansion only `/@` and `/users` on the same host. PHP moderation aliases and Search canonicalization include more identities (`api/ap-db.php:11315`, `:11433`). Native Bluesky DID moderation uses `api/ap-bsky.php:9199` and `api/ap-visibility.php:6`, absent from `load_hidden_sets`.
- `api/ap-visibility.php:112` recursively moderates boosts, quotes and quote previews; `:167` rechecks current durable audiences, recipients, delivery evidence and followers, and fails closed on policy-store failure. Rust `audience.rs` has equivalent durable lookup structure, but `Surface::Profile`/Local/Federated enforce public-only roots. A saved Library item or explicitly opened detail requires a distinct direct-read audience contract: authorized unlisted/private/direct/local content must not disappear merely through use of a discovery surface.
- `rust/vaak-worker/src/search.rs:137` generates every minimal candidate with `visibility=public`, `sensitive=false`, empty spoiler. `project` checks only candidate authors, not recursive moderation or durable audiences. Reusing those statuses as native page render input would lose CW/private metadata, quoted content and current eligibility. Its generic query also lacks PHP source-liveness and precise hashtag predicates (`api/ap-search-fts.php:426`), so stale/local deleted indexed rows need explicit comparison.
- Rust Search account candidates do not have PHP complete account serialization or self-visibility exception (`api/ap-db.php:11410`, `:11467`); PHP intentionally leaves own account visible. `discoverable` means directory/suggestion consent, not a blanket denial of explicit handle lookup; do not invent a new exclusion. `indexable` is current canonical post-index eligibility with own-author exception (`api/ap-search-fts.php:441`), including stale docs/event mirrors. `collection_consent` applies featuring, not reading saved posts.
- Muted phrases normalize decoded HTML, whitespace and Unicode lowercase (`api/ap-db.php:11676`); row helper also examines CW and boost/outbox text (`:11721`). Rust recursive helper exists but Search does not invoke it. Preserve per-surface PHP behavior; establish canonical query/controller expectations before claiming that every current PHP Search path already applies every muted-word filter.

## Library identity and private source contract

`ap_masto_interaction_row_to_status` (`api/ap-masto-entities.php:13395`) handles RSS owner scope, synthetic numeric IDs, Announce unwrap, fragment stripping, URL lookup, safe stub recovery, and favourite/bookmark flags. It keeps the original interaction ID after unwrap so undo forms address the saved row. `admin_library_status_enrich` (`api/ap-admin.php:21867`) retains ID/flags after cache hydration or budgeted signed remote fetch. `admin_render_library_status_card` (`:21957`) uses owner-scoped RSS rendering and shared canonical card. Rust `library.rs` projects owner-scoped raw rows only; that does not establish hydration, policy or action parity.

Bookmark folders are personal: every operation scopes owner; delete removes folder memberships but preserves bookmarks; unbookmark cleans memberships (`api/ap-bookmark-folders.php:143`, `:172`, `:215`, `:235`). Action dispatcher and response semantics begin `api/ap-admin.php:1611`. Keep canonical PHP mutations until their full output/persistence/CSRF/side effects have independent native parity.

## Settings and actions to retain

- CW renderer `admin_cw_gate_html` (`api/ap-admin.php:15197`) permits auto-unblur only sensitive-without-custom-CW. Explicit CW stays collapsible. Bluesky adult labels also gate media (`:19785`). Reply composer inherits parent CW/sensitivity (`:11574`, `admin_reply_cw_query :17039`). Verify first paint, soft navigation and paginated cards.
- Saved profile hiding preferences are evaluated on profile tabs/counts (`api/ap-admin.php:31909`, `:32070`; `:20878`). Hide replies/boosts, current local avatar and automated identity must survive metadata refresh and cache reads.
- Reply/quote policies are emitted per saved profile via `ap_note_interaction_policy_for_actor` (`api/ap-db.php:14123`), carried into local publication (`api/ap-inbox.php:6063`), and inbound quote requests are enforced (`ap_handle_quote_request :5401`; automatic remote quote checks `:5612`). Rendering a permissive default quote approval from lean serializers cannot stand in for that enforcement. Exercise the actual outbound/inbound/helper paths rather than asserting button presence alone.
- Block/unblock may federate and sync Bluesky; owner state changes, queueing, redirect/AJAX shape and cache invalidation are part of action parity (`api/ap-db.php:11240` vicinity; `ap-admin.php` dispatcher). Bookmark/favourite/boost undo IDs, connected Bluesky record IDs and folder memberships must survive native render.

## Required regression fixtures

1. Two owners: favourite/bookmark/folder/RSS identities, another owner’s folder ID, forged RSS ID, same remote post saved by both, independent flags/actions. Real canonical DB helpers, not replacements that always return allowed.
2. Public/unlisted/private/direct/local notes plus accepted local follower, pending follow, explicit recipient, unrelated logged-in viewer, guest. Quote/reblog/parent embeds with different audiences. Revoke follow or delete note after warming HTML and verify next read.
3. Actor/domain blocks including subdomain, global mute, personal mute, native Bluesky mute/block/list DID, `/@` versus `/users`, local web versus canonical AP hostname, HTTP host and trailing slash. Direct profile personal-mute exception versus nested author filtering; deprioritization changes ranking without hiding.
4. Canonical index opt-out after FTS/cache warm, same owner exception, mirrored event actor, missing/deleted source. Keep account explicit lookup versus directory/discovery consent distinct. Accurate hashtags and owner-followed state without unrelated private source counts.
5. Sensitive media with/without CW under auto-unblur on/off, Bluesky adult label, quote/parent CW and reply prefill; saved profile hide replies/boosts on/off and refresh after toggles.
6. Synthetic Announce interaction ID retained on original card; stale URL-only stub, media-only, RSS, native Bluesky and crosspost twins. Undo removes correct interaction/membership and never another owner’s row.
7. Reply/quote anyone/followers/nobody; real local publish policy and inbound QuoteRequest allow/reject; remote quoted post approved/unauthorized; rejected or not-yet-approved quote content must not become a permissive rendered quote through lean hydration.
8. Action HTTP contracts: authenticated owner and CSRF, forbidden/invalid targets, optimistic AJAX success/failure rollback, durable flag after reload, pending delivery state, cache invalidation after preferences/mute/block/action changes. Differential execution against canonical PHP on isolated databases, plus normalized HTML/action attributes and browser interaction tests.

Any discovered canonical PHP privacy defect should be documented and repaired deliberately, not silently cloned or labeled parity. A row-count match or source-pattern test cannot establish these policies.
