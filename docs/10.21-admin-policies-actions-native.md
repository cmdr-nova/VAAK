# Admin policies saves native (step A10b)

The worker saves the three Policies editors: `policies_save_privacy`, `policies_save_conduct` and `policies_save_rules`. PHP keeps the session, CSRF, the admin-only gate, the notice and error text, and the page. It uses the same `/internal/admin/action` route, bridge and reply as A10a (`10.21-admin-downranking-actions-native.md`).

Admin only. Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` plus `VAAK_ADMIN_POLICIES_ACTIONS_NATIVE=1`, in both `www.conf` and `vaak.env`. Each family has its own switch: the downranking one does not open this one.

## What it does

Copied from `ap_instance_doc_save` and `ap_instance_rules_save_from_text`, inside a transaction that first reads the acting account `FOR SHARE` (an active admin with the actor key PHP sent):

- privacy or conduct: the title trimmed, the default title when empty, at most 120 characters; the body as sent (not trimmed), at most 100000 characters; the same `INSERT … ON CONFLICT(doc_key) DO UPDATE`.
- rules: the text split on PCRE2's `\R` (CRLF, LF, CR, VT, FF, NEL, U+2028, U+2029), each line trimmed and stripped of a leading `1.` or `1)` marker with its whitespace, empty lines skipped, at most 40 rules of at most 500 characters, checked in order as PHP does; then every old rule deleted and the new ones inserted with `sort_order` from 1.

The reply's outcome is `doc_saved`, `title_too_long` or `body_too_long` for the documents and `rules_saved` (with `count`), `rule_too_long`, `too_many_rules` or `no_rules` for the rules. PHP shows its usual notice or error. The bridge rejects a count anywhere but a successful rules save, a count outside 1 to 40, and the outcomes of other actions. The request may be up to 512 KiB, since a document body may be 100000 characters; a larger JSON body stays in PHP.

Runs in PHP instead when the text holds a NUL (PostgreSQL refuses it and PHP reports that its own way), the account is not an active admin with that actor key, or any query fails. Nothing on these pages is cached, so there is no after-save work.

## Parity check

`api/bin/admin-policies-actions-native-review.php` (sandbox only) runs the genuine handler chain from `ap-admin.php` with the genuine save functions against a seeded PostgreSQL fixture. For each scenario it runs PHP with the switch off, reseeds, runs the native branch with PHP's handler disabled, and compares the notice, error, view and every row of `ap_instance_docs` and `ap_instance_rules`. It also checks the fallbacks write nothing, the bridge validator, and that another family's switch keeps PHP. Run the worker with `VAAK_ADMIN_POLICIES_ACTIONS_NATIVE=1`.

Scenarios cover updating and inserting each document, default titles, Unicode and HTML text, the 120 and 121 character titles, the 100000 and 100001 character bodies, rules with list markers, CRLF and every Unicode line break, exactly 40 and 41 rules, 500 and 501 character rules, a long rule after the 41st, empty and marker-only text, and a save into an empty documents table.

2026-10-21: 80/80 checks with INTEGER ids and 80/80 with BIGINT ids.
