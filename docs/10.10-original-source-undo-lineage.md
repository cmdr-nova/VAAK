# Original post authority versus undone interactions, 10.10

This is a confirmed PHP correctness and privacy correction, separately from Rust parity. No feature flags were enabled and nothing was committed or deployed.

Independent review found Search and direct-view liveness queries considered any latest `events.action_taken='deleted'` row a deleted post. The actual `ap_events_mark_interaction_undone` writer marks Announce, Quote and QuotePost interaction rows `deleted`, while their `object_id` can be the original target URI. Therefore Undo of a boost or quote could hide a still-live original Create.

`api/bin/search-direct-undo-smoke.php` executed the real writer. Before correction, six controls reproduced a persisted live Create plus a later same-target undone Announce, with both canonical Search and direct predicates denying the original. Extending the real writer to Quote and QuotePost proved that removing the broad deleted-action condition alone was insufficient: both types were also inside the note-source type list. The probe `--probe-quote` exports the actual persisted event rows and predicate decisions.

The verified producer source uses `ap_as_id(activity.object)` as `object_id` in `ap_route_verified_activity` and passes that same value into `ap_metrics_record` for interaction observation/generic log; its Undo branch passes the inner target into the actual Undo writer. This source trace and execution of the actual writer establish the storage ambiguity. The fixture does not claim complete signed inbox routing or delivery.

A second actual-helper/full-card probe found an audience leak: a private original Create denied the viewer, then a newer public Quote by another actor on that same target caused `ap_visibility_status_audience_allowed` to use the quoter's public audience. Both Search and direct cards exposed the private original body. `--probe-quote-audience` recorded all five decisions true before the correction; now audience, Search, direct and their complete card body decisions are false.

## Narrow authority contract

The Search, direct and Library current-deletion selectors now consider:

- Create, Update, Delete and Tombstone rows for the original URI/root-slash aliases.
- Quote and QuotePost rows only when **no durable Create or Update lineage exists for that URI**.
- Within that source selection, latest Delete/Tombstone or `deleted` source state still denies the original. A deleted Create/Update is still durable lineage; a public quote cannot bypass its withdrawal.

The shared audience selector applies the same Create/Update lineage precedence, retaining its existing live-action filter. Legacy sources known only through Quote/QuotePost retain their previous public/private and deleted-source semantics. This does not use a cached account identity to guess which actor owns an ambiguous interaction row. Actor moderation, indexability, muted words and source-less saved-snapshot compatibility rules are otherwise unchanged.

Each new query supplies four parameters: original root, root plus slash, original root, root plus slash. The bounded `NOT EXISTS` probes the same exact object aliases rather than scanning all interactions.

Normal mention Undo needs no additional policy change. Production Like/Reblog notifications use `root#like-hash` and `root#reblog-hash`; normal notifications are restricted to the recipient's local target notes. The real `ap_mention_soft_delete_interaction` writer matches activity ID or these stable keys, preserving the bare Create source. Four actual writer controls prove this; its notification projection invalidation is an isolated cache IO boundary in the fixture. Unproven legacy malformed notification rows did not justify a broader filter.
