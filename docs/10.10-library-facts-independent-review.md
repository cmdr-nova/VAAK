Confirmed defects before remediation:

1. `library_source.rs` extracts a FeedView wrapper's `post` and stores only that inner object as `bsky_post`. The actual PHP admission rejects a wrapper whose `reason.by.did` is hidden. Actual native source hydration drops that reason, and the same native policy changes from hidden before hydration to visible afterwards. Preserve the entire authoritative wrapper for policy. Normalize a separate inner PostView for display: the shared materializer's facet, mention, CID, label and reply readers generally expect top-level PostView fields, so passing the wrapper unchanged to those readers is insufficient.
2. `library_facts.rs` assigns own edit sensitivity from the stored `sensitive` flag alone. With flag zero and a nonempty stored CW, native emits false; the actual PHP painter at its own edit branch uses `!empty(sensitive) || trimmed_spoiler !== ''`. Match trimming and effective sensitivity, including edit data and reply CW behavior.
3. Native Wafrn membership applies actor-scope server blocks to directory URL references. Actual PHP `ap_wafrn_actor_host_known` uses friend inboxes and `ap_is_blocked_inbox`, whose rule examines domain blocks only. With `https://sub.remote.test/` in the directory and an actor-only block for `https://sub.remote.test`, actual PHP membership is true and actual native facts membership is false. Preserve the canonical host/domain predicate and hostname validation; do not invent a new actor-to-instance exclusion. The PHP directory limit counts inboxes, while native currently deduplicates hosts before its limit, another boundary to compare explicitly.
4. Original native policy walks the entire normalized JSON starting at depth zero. PHP begins a native policy walk only at `bsky_post`, at depth zero. Actual PHP permits native child chains through depth 16 and rejects depth 17; native originally rejects the depth-16 case because of its extra status wrapper. PHP also permits unrelated normalized metadata with an 18-deep tree or `metadata.viewer.blockedBy`; native originally rejected both. The native implementation agent has made a scoped correction; a fresh full paired rerun remains required.
