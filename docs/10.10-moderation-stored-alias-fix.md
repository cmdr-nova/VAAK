# Stored moderation alias/cache correction (2026-10-10)

Actual PHP/native Library policy comparisons exposed canonical PHP privacy omissions for stored URL-encoded actor identities. A stored `https://host/users/%61lice` personal block did not hide its literal `/users/alice` or `/@alice` candidate; global server mute comparisons expanded only the incoming side. These are deliberate PHP baseline corrections, not an imitation of a native implementation gap.

Personal actor block sets now expand the existing syntactic aliases of stored rows alongside existing cache-backed DID/handle aliases. Global server mute comparisons expand both stored and incoming syntactic refs. Existing personal block/mute and server block path case remains significant; global server mutes intentionally retain case-insensitive comparison. Numeric actor `/users/123` does not acquire `/@123` identity equivalence. The existing syntactic parser rules are reused; this change does not add new ActivityPub identity equivalence.

Compact keys are versioned so old omitted-alias sets are never read: personal blocks use `vaak:relset:v2:blocks-actors:<owner>`, personal mutes `vaak:moderation:mutes:v3:<owner>`, server blocks `vaak:moderation:server-blocks:v2`. Owner invalidation deletes exact old/new keys. Server block/mute cache clearing now also resets its compact actor-set memo and exact old/new Redis keys, avoiding a warm set reviving a removed block. No global Redis flush is used.

`api/bin/php-policy-test api/bin/moderation-alias-cache-smoke.php` passes 39 controls executing actual PHP alias/set/admission/invalidation helpers against isolated SQLite and a deterministic Redis transport. Cases pair literal/encoded stored/candidate forms, canonical/web aliases, case controls, numeric non-aliases, owner isolation, stale namespace refusal and warm unmute/unblock/server-clear behavior. The Library admission fixture remains 61 passing actual-helper cases and existing moderation smoke remains 30 passing checks. Full PHP/native cross-database comparison is the independent acceptance gate. No deployment, commit or cutover accompanies this correction.
