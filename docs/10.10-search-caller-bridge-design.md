# Search presentation bridge design, 10.10

Integration contract against the current checkout. The separate Rust Search HTTP bridge is implemented and remains disabled by default; its typed status/context and component gates are independently verified within their documented supported branches. PHP caller integration and combined independent bridge review remain pending. This document does not activate native Search or claim complete parity.

The early full-page pasted-post URL resolver around 21800 performs resolution and author-block checks **before HTML**, then sends a 302 to status detail. `admin_search_run` intentionally returns empty for a recognized pasted status URL. Retain this orchestration in PHP; replacing the painter must not turn it into a text search or introduce a second resolve request.

`admin_search_run` 12111 clamps limit to 1–40 and collector offset to 0–160. Its ranked status window is 121; tag window is 80. It retains fresh initial text search, cached later pages/tag queries, owner/query/resolve keyed cache, current permitted tag recount, current Search status filtering, account-resolution behavior and network budgets. Returned arrays are already section windows. A bridge consumes those arrays once; it must not call the old lean `search::project`, search again, backfill dropped cards, re-rank, or adjust source limits.

Summary counts are `count()` of the three returned arrays, with `has_more` controlling `+` and singular/plural, **before final card omission**. Initial list offsets are likewise raw array counts. Append wrapper next offset is the original fragment offset plus raw row count; its current has-more is `rows !== [] && bundle.has_more[section]`. This retains the existing offset-clamp behavior at large offsets; do not silently fix it in a presentation patch. A current-admission rejection may produce zero articles with an advancing cursor and has-more true. The repaired loader continues that page (actual before/after browser evidence is in `10.10-search-loader-browser-review.md`). Never replace these cursor/count values with rendered-card counts.

## Smallest complete integration

Keep summary and all list/fragment wrappers in PHP. Add one batch presentation helper used by both `admin_search_render_sections` and `admin_search_page_fragment`, returning **all section card strings or null**, before emitting any section card. The initial full/shell request makes one bridge call for its selected nonempty sections; append makes one call for its section. No per-card RPC. PHP summary is already exact and avoids exposing a new summary API merely to route card rendering.

Create a separate, default-off `api/ap-search-native.php` and authenticated `/internal/search/render` Rust handler, with independent Search flag/secret/header and strict loopback URL allowlist. Model transport limits on `ap-library-native.php` and `library_bridge.rs`: HTTP loopback only, exact endpoint, no URL credentials/query/fragment, no redirects/proxy, connect 200ms, total 3000ms, 2 MiB request and 8 MiB response cap. Keep Library's constructor and endpoint restricted to bookmarks/favourites. Do not add Search to Library's allowed views.

Minimum strict envelope:

- Positive current authenticated PHP owner ID, fresh `ap_auth_csrf_token()` and current `ap_bsky_tab_enabled()` result. Search has no guest route: the existing session gate permits guests only for explicit remote profiles. Rust rechecks an active current owner. Browser query data cannot supply owner, CSRF, following, audience, self status, saved flags, permissions or admitted tokens.
- Three ordered arrays of exact canonical accounts, hashtags and complete normalized statuses for the selected windows; each section at most 40, total at most 120. Do not flatten groups or turn numeric IDs into JavaScript numbers. Retain opaque source IDs and all status fields, including reblog/quote source trees, native Bsky payloads, Ask/media/poll/link preview descriptors and interaction URLs.
- Current owner native Bsky bookmark provenance tuples `(uri, did, bookmarked)` only where represented in the complete status tree. Recursive URI collection, exact AT post URI validation, unique tuples, current session DID and bounds must be checked. Do not blindly reuse Library's root-only bookmark collector: nested quote/reblog native posts can need their own represented state. Missing authority must trigger fallback, never a guessed saved flag.
- No client `return_view`, lazy-media toggle or policy bits: Search return view is fixed and its presentation session fixes lazy media to false. Current auto-unblur, own editing state, moderation, subscriptions, relationships, tags, emoji/profile state and audience come from DB-backed typed resolvers.

The PHP producer must preserve original collector rows separately from any cache-only assembly copy. Use canonical normalization/cached complete quote assembly without changing query budgets or doing speculative signed fetch/AppView/OG IO. The existing Library cached assembler can be a reference, not automatic Search authority: it recognizes only certain compact quote shapes and PHP's actual Search painter can recover additional sources late. A missing/thin/RSS/unknown body-bearing quote must explicitly fall back for the complete batch. PHP fallback must paint the preserved canonical rows using the existing account/tag/status helpers, with their original recovery behavior; it must not repaint enriched/rewritten copies that changed descriptor state.

Rust creates `SearchSession`, calls current Search status admission and builds the private `AdmittedSearchStatus` tokens, then `library::card::render_search_admitted`. Load `ComponentContext` once for the complete account batch, bind each exact account input, resolve private account/tag tokens, then call `search_render::render_account`/`render_tag`. Do not use convenience per-account context loads. Component tokens alone are presentation facts, not status admission. Await the separate current-context gate review before wiring this path.

Response should be strict `ok: true` with three ordered arrays of HTML strings and source counts matching the supplied section arrays. Require exact account/tag output slot counts (an empty tag painter may return an empty string); statuses may be omitted only through successful current source admission. Group/type/count mismatch, body overflow, non-200, malformed reply, renderer error, unsupported source, unknown numeric/dynamic alias or DB failure returns null to PHP for **all selected sections**. Hold all native output until every section succeeds; no native account section followed by PHP statuses after a late quote failure. Preserve source order within sections and empty successful status output as distinct from transport fallback. Exact source-index slots for status output are preferable for validation, especially when admission omits cards.

## Interoperability boundaries requiring explicit checks

`ap-library-native.php` currently serializes using `JSON_INVALID_UTF8_SUBSTITUTE`. Do **not** copy that into this Search bridge: repairing invalid identity/URI/content bytes before admission can change both authority and PHP output. Use strict `json_encode` with throwing/error handling and return null on invalid UTF-8, recursive values or unsupported values; leave original PHP rows available. Valid significant Unicode must survive unchanged. Existing PHP `h()` uses HTML substitution at the output boundary; that does not authorize mutating source JSON before policy. Invalid reply UTF-8/JSON also falls back. This is a proposed Search transport contract, not a change to Library.

Canonical account actions currently include self/profile routing, following badge, `follow_remote` with return view Search, and external profile links. Tag cards retain View posts soft navigation, `follow_tag` returning to Tags and Manage. These account/tag forms currently omit an explicit hidden CSRF field; preserve the reviewed canonical component markup rather than inserting an unrelated form change. Status cards retain the complete established action menu and composer/gallery/poll/quote/hydration hooks, current ownership and protocol behavior, with CSRF from the trusted session. Existing PHP POST handlers and action routing remain the authority.

Account aliases have tested legacy semantics: UI following case/host aliases and numeric account-ID fallback use different resolution paths; uncached `/users/name` versus `/@name` CRC behavior must remain canonical. Current Bsky cache lookup uses exact DID, plain profile DID URL, encoded profile URL, then latest by DID; malformed chosen JSON cannot silently select another row. Cold/unknown evidence is an explicit whole-batch fallback. Do not invent profile-private field scoping for global public cached handles.

The PHP painter `admin_render_masto_status_card` 17256 normalizes Asks and may recover thin boosts/quotes; its final Search gate around 17994 checks root and displayed recovered sources immediately before HTML. A producer that merely sends cached initial roots cannot assume all eventual displayed authority is present. The native gate's source-backed rejection/error split and complete current audience/indexing checks must be proven separately. Successful fallback is compatibility coverage, not proof that these branches have native parity.

## Rust handler implementation checkpoint

`search_bridge.rs` implements the agreed independent flag/secret/header and 2 MiB strict request / 8 MiB strict response boundary. It receives no return-view or lazy-media capability. The batch constructs a server-only Search session, validates represented recursive native bookmark tuples against the current connected DID, loads one component context, admits exact status sources with private tokens, and holds every card until all painters succeed. Original section counts are returned; status cards carry strictly increasing zero-based original `source_index` values, preserving omissions and duplicate source IDs without matching by identity. Active owner actor/key is checked again before successful output. No source query, re-ranking, external enrichment, or PHP authenticated write was ported here.

Three targeted tests cover strict source/session/UTF-8/provenance limits and actual ephemeral HTTP disabled/auth/decode/body/error responses. `api/bin/search-bridge-postgres-fixture.py` emits the full real module graph and passes actual HTTP requests over disposable INTEGER and BIGINT schemas: exact verified account/tag/status token HTML, original source counts, omitted middle index and duplicate slots, all-or-nothing failure after earlier component resolution, owner switch/inactive account-only batches, and foreign-DID provenance rejection. Its schema-only additions supply genuine component columns/tables missing from the prior status fixture. Independent PHP producer/consumer and mixed full/shell/append review remain required. The registered production route is absent unless `VAAK_SEARCH_NATIVE_RENDER=1` and an independent secret of at least 32 bytes are configured; no configuration was changed.
