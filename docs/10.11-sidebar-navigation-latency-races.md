# Trending sidebar navigation timing — 2026-10-11

History navigation could leave Trending empty indefinitely. The main controller schedules the lazy rail when installing its new view, then awaits timeline/scroll restoration. If the browser executes the idle callback during that await, the callback correctly refuses a background request while navigation is pending, but consumes the only scheduled load. Clearing the navigation flag did not schedule another load. Subsequent resize, scrolling or navigation could make the cards appear unexpectedly.

Completed soft navigation now re-arms the lazy loader after draining any queued destination, except when authentication denial or a full-navigation fallback is leaving the document. A newly queued main request still takes priority. Only successful direct timeline swaps re-arm the current connected view, including a same-view request. Authentication denial keeps previous cards cleared and sends no extra sidebar request. Invalidation gives each scheduled callback a ticket, preventing callbacks from a previous context from starting work for a newer one. A response discarded offscreen also re-arms if a visible-again callback coalesced before its request finished.

The scheduler still waits for parsing, two paint opportunities and browser idle (maximum idle timeout 1.5 seconds). There is no polling, browser HTML cache, policy bypass or stale-card retention. The main column, document, composer and scroll position are unchanged by the sidebar fix. This does not establish the cause or reduction of the user's measured 12-second server delay; server query and session concurrency are investigated separately.
