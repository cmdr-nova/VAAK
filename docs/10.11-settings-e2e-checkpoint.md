# Settings SAPI save → current native read checkpoint

The isolated browser-transport gate passes **1,082 checks / 29 retained captures**. It adds real HTTP form decoding, PHP sessions/cookies, current authenticated-user lookup, CSRF rejection, and the unchanged pre-publication Settings save action to the existing PostgreSQL/native projection evidence. No production runtime file changed. This is bounded evidence, not complete Settings/backend parity.

`api/bin/settings-e2e-reference.php` starts the actual worker and a loopback PHP development server with `settings-e2e-router.php`. The router accepts only the PHP development-server SAPI and loopback clients, requires a unique test schema, and is never included by production. The source extractor loads genuine authentication/profile declarations. Exact source slices execute the application session gate, CSRF branch and `save_profile` body through its real email update and profile save. The save slice ends before publication, Bluesky synchronization and success-toast handling. Individual branch hashes and complete runtime hashes are retained.

The test owns its schema and session files. It reserves two kernel-selected loopback ports simultaneously, releases them immediately before starting its owned processes, checks process liveness during readiness and every request, and verifies a random per-run SAPI response identity. Unique initial profile names and exact PHP/native comparison identify the owned worker's schema. A competitor winning the brief bind race causes failure rather than reuse. Listener ports and run identity are retained in the artifact. Schema columns, widths, nullability/defaults and the initial profile row come from the prior Settings reference artifact; genuine primary/unique constraints are added explicitly. Sessions are preseeded for established test users. This tests session authorization, not password login, account linking or 2FA. Genuine `ap_auth_bootstrap` takes its existing seeded-`cmdr_nova` early return; top-level module/migration bootstrap is omitted. DB/session paths and request-local Redis/cache invalidation are isolated transports. No upload file, URL attachment, public export, federation delivery or external integration is exercised.

The first attempt omitted primary/unique constraints while rebuilding the captured schema and failed the genuine `ON CONFLICT` save. That test-infrastructure failure is preserved in `/tmp/vaak-settings-e2e-initial-failure.log`; constraints were restored, with no change to expected native data or production code.

## Observed behavior

- All 15 advertised boolean form controls can be enabled independently. Omitting checkboxes clears them, matching the complete HTML form rather than the partial-helper semantics proved by the earlier writer reference. The hidden legacy `anti_ai_marker` is forced off by the actual controller even when submitted on.
- Unicode bio/signature, badges and paired attachment fields survive real URL-encoded POST parsing and current native reads.
- Forged POST/query owner IDs, actor keys and administrator flags do not change the authenticated owner; the second user's complete native projection stays unchanged.
- Anonymous, missing-token, wrong-token, cross-session-token and disabled-existing-session requests are rejected before profile/user writes. Invalid email prevents profile saving.
- All three interaction-policy values execute the genuine `ap_note_interaction_policy_for_actor` mapping after saving. Collection-consent and Webmention target getters track the current saved flags. These are getter/policy construction checks, not inbound Ask acceptance, collection import, Webmention receipt or enforcement of a remote actor's interaction request.
- Every successful capture compares all 26 canonical native fields to the genuine current PHP getter. The actual PHP loopback bridge and Rust `/shadow/settings` endpoint supply the response; no substitute SQL/native decision supplies it.

`admin_settings_projection_axum_fetch` currently has **no production call sites**: Settings forms still read PHP. This fixture calls that helper explicitly to verify the native projection. A read projection alone must not be described as a migrated editor or authenticated public API.

## Reproduction

First produce `/tmp/vaak-settings-postgres-native-reference.json` using the existing reference runner, and build a fresh worker. Then run with real mbstring, curl and PDO PostgreSQL:

```bash
LIBRARY_FIXTURE_SOCKET=/tmp/vaak-library-facts-pg-socket \
 api/bin/php-policy-test \
 -d extension=/tmp/vaak-php-pgsql-test/extracted/usr/lib/php/20230831/pdo_pgsql.so \
 api/bin/settings-e2e-reference.php
```

Artifact `/tmp/vaak-settings-e2e-reference.json` retains responses/headers, current profile rows, scoped user rows, explicit substitutions and source/binary hashes. The runner terminates its two processes, drops its own schema and removes its session files in `finally`. Shared disposable PostgreSQL remains untouched. Loopback/socket sandbox escalation is required. PHP syntax and `git diff --check` pass. No flags activated, production writes, commit or deployment.
