# Admin AP stats native read (step A8, first part)

Rust paints the whole AP stats page (`?view=stats`): the eight instance totals, the Local users table (posts, followers, following, open mentions and admin/disabled flags per account) and the 24h firehose breakdowns by activity type, action and host. PHP keeps the shell, the session and the admin gate; the page has no forms or actions.

Admin only. Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` plus `VAAK_ADMIN_STATS_NATIVE=1`, in both `www.conf` and `vaak.env`. When the native body arrives, PHP skips its own eleven stats queries.

## What it does

`ap_admin_native_read_body('stats')` posts the usual admin envelope with offset 0 and no selectors. The worker requires a current active administrator before and after a READ ONLY transaction and runs the same queries as the PHP block:

- Firehose totals over `events` for the last 24 hours and 7 days, with the cutoffs as `gmdate('c')` text, as PHP binds them.
- Top 12 types, actions and hosts in the last 24 hours. Both PHP and Rust now break count ties by label (`ORDER BY c DESC, <label> ASC`). Before, PHP left tied rows, including which ones made the 12-row cut, in whatever order the plan returned.
- Account, active account, outbox post, follower, following and open-mention totals.
- Per user, ordered by id: posts keyed by the lowercased fifth path segment of local outbox ids, followers and following keyed by `owner_actor_id` with trailing slashes trimmed, open mentions keyed by `(int) owner_user_id`. Each account's key is `actor_key ?? username ?? ''`, so an account with neither reads the counts PHP files under the empty key.

Rows are `{id, username, posts, followers, following, mentions, is_admin, disabled}` for at most 1000 accounts, in strictly increasing id order.

Renders the PHP page instead when: two source rows land on one PHP array key (PHP keeps whichever the unordered GROUP BY returns last), `mentions` lacks `deleted_at` (PHP retries without it), any query fails (PHP shows a partial page), printed text matches the `ap_fix_utf8` mojibake pattern that `h()` would repair, there are more than 1000 accounts, or the session is not a current active administrator.

## Parity check

`api/bin/admin-stats-native-review.php` (sandbox only) runs the genuine data block and template with the genuine `ap_db_execute_retry`, `ap_db_is_locked_exception` and `h`, and compares whitespace-collapsed HTML in full and shell modes for two admins. The fixture has 15 event types with ties at the 12-row cut, NULL actions and hosts, 3-day and 9-day events, mixed-case outbox keys, a trailing-slash following key, a NULL follower owner, deleted mentions, a disabled account, an account keyed by username, and an account with no username or actor key. With no events it shows the empty state. The real bridge validator must accept each reply and reject a string count, an int flag, an extra key, unordered ids and an extra binding. Fallbacks: every case listed above, plus ordinary, disabled and unknown accounts, a nonzero offset and a role selector.

2026-10-21: 75/75 checks with INTEGER ids and 75/75 with BIGINT ids.
