# 10.6 Library/You parity plan

PHP remains the behavioral reference, renderer, and mutation owner. Rust/Axum
is read-only until a surface passes its contract smoke, account-isolation
check, and browser/mobile comparison.

| Surface | Rust projection | PHP-owned work | Promotion gate |
| --- | --- | --- | --- |
| Favourites | Owner-scoped Fediverse/Bluesky rows and pagination | Card hydration, favourite/unfavourite, sync | Contract smoke + account switch |
| Bookmarks | Owner-scoped rows, folder filter, pagination flags | Cards, folder CRUD/membership, bookmark mutations | Contract smoke + folder UI test |
| Followers/Following | Owner-scoped relationship rows | Follow/unfollow, graph sync, invalidation | Relationship smoke + account switch |
| Blog/RSS/Queue/Drafts | Owner-scoped primary/secondary rows | Rendering, compose, queue, draft, and cross-post writes | You smoke + browser navigation |
| Settings/Security/Import/Phyrian | Read-only settings projection only | All writes and sensitive integrations | Field fixtures, CSRF, rollback, mobile parity |

## Current decision

The first four Library/You read paths are safe to keep shadowed behind PHP
fallbacks. No mutation or privacy-sensitive write moves until the remaining
Settings/Security/Import/Phyrian and DMs/Asks gates are complete.

## Verification record

- `api/bin/library-client-smoke.php` passes owner scope, folder filtering, row
  arrays, pagination flags, and the PHP write-owner marker.
- `api/bin/you-client-smoke.php` passes Blog, RSS, Queue, and Drafts owner
  scope, primary/secondary row shape, and the PHP write-owner marker.
- Browser account switching and Library/You navigation were verified on live.
