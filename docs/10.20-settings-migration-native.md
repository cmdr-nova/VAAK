# Settings Import / Export native read (step S6)

Rust paints the two per-account reads on the Import / Export page (`?view=import_export`): the alias list under "Migration — aliases" (one card per alias with its direction, verified tag, actor URL, and the Verify remote and Remove forms) and the Move followers state (the Active Move card with Clear movedTo, or the Move out form with its cooldown notice). PHP keeps the shell, the session, the page's static text, the export links and CSV downloads, the import form, the follow import job card, every alias and Move action (`alias_add`, `alias_verify`, `alias_remove`, `move_out`, `move_clear`, `move_prepare_target`) and CSRF injection.

The follow import job card stays PHP: `ap_ie_follow_status` reads a state file shared with the CLI importer, not a table, and the worker should not read the web server's files.

Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` plus `VAAK_SETTINGS_MIGRATION_NATIVE=1`, in both `www.conf` and `vaak.env`. One flag covers both views. The page is open to every active account, never admin-gated.

## What it does

`ap_settings_native_body('settings_aliases' | 'settings_move', $viewerAdmin)` posts the usual envelope with offset 0 and `viewer_admin`. The worker requires the owner to exist, not be disabled and have exactly that admin role, before and after a READ ONLY transaction.

Both views key on `vaak_actor_key()`: the account's actor key (NULL reads as `cmdr_nova`, as on the page), trimmed, lowercased and reduced to `[a-z0-9_]`. Aliases copy `ap_alias_list`: `ORDER BY direction ASC, created_at DESC`, shown by `alias_acct ?: alias_actor_id`, verified when `verified_at` is non-empty. Rows are `{id, verified}`, at most 1000.

Move copies `ap_move_get`, `ap_move_active_target` and `ap_move_cooldown_remaining_seconds`: a move is active when `moved_to_actor_id` with trailing slashes trimmed is non-empty and `cleared_at` is empty; otherwise the Move out form shows `ceil(remaining / 86400)` days while `moved_at` plus 30 days is in the future. The row is `{panel: "move", state: "active" | "none"}`.

Renders the PHP section instead when: the actor key reduces to nothing (PHP then tries other fallbacks), two aliases share direction and `created_at` (PHP leaves their order to the query plan), `moved_at` is not `gmdate('c')`, offset-bearing Postgres text or zoneless `Y-m-d H:i:s` (read as UTC, the only zone the envelope admits), printed text matches the `ap_fix_utf8` mojibake pattern that `h()` would repair, a table is missing (PHP shows the empty state), the account is unknown or disabled, its admin role changed, the session owner differs from the page owner, or anything else in the bridge refuses.

## Parity check

`api/bin/settings-migration-native-review.php` (sandbox only) renders the genuine template regions with the genuine `vaak_actor_key`, `ap_alias_list`, `ap_move_get`, `ap_move_active_target`, `ap_move_cooldown_remaining_seconds`, the page's own setup block and `h`, and compares whitespace-collapsed HTML in full and shell modes for: the operator with verified, unverified, empty-acct, `'0'`-acct and escaped aliases and an active move with trailing slashes; an ordinary account with a cleared move cooling down; a NULL actor key (reads as `cmdr_nova`); a padded mixed-case actor key; and an admin with neither. Edge cases: zoneless and Postgres `moved_at`, a `'0'` `moved_at`, an active move with no acct or date, and a `'0'` `cleared_at`. The real bridge validator must accept each reply and reject a non-boolean verified flag, an extra row key, a bad id, an unknown Move state, another panel, two Move rows and a flipped role binding. Fallbacks: every case listed above, plus missing role and nonzero offset.
