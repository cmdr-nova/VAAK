## Nested synthetic RSS correction

Fresh independent review found that both native typed rendering and the canonical PHP shared painter accepted an outer public card containing another owner's synthetic RSS child. The actual PHP repro returned `allowed=true` and rendered `PRIVATE SUBSCRIPTION SNAPSHOT`; native INTEGER/BIGINT did the same. This was an inherited privacy defect, so the canonical correction is deliberate rather than a parity exception silently introduced by Rust.

Every synthetic RSS object now binds recursively to a current owner-joined row before rendering. Foreign, deleted or malformed child sources deny the containing card. Current-owner children use fresh titles, summaries and subscription identity; ownership changes and newly muted text are rechecked. Native admission repeats the binding after source materialization. PHP also rebuilds synthetic RSS quote options from the fresh row for late cache recovery. Ordinary foreign public AS2 mirrors remain ordinary public statuses without the other owner's feed metadata.

`api/bin/php-policy-test api/bin/library-nested-rss-php-reference.php` passes 21 actual PHP complete-painter controls for quote, reblog and compact children, malformed/deleted/foreign rows, current title/summary, changed ownership/muted words, and preserved foreign public AS2. The independent reviewer owns the expanded real PostgreSQL regression fixture. ASCII whitespace on an already classified synthetic `rss:` ID follows the actual PHP RSS parser; contradictory/malformed synthetic IDs cannot be rescued by another item's numeric metadata.

Bookmark provenance envelopes now require exact AT post URI grammar and an exact represented source URI in the batch, then bind the source DID to the current owner's stored session. Cached global booleans remain non-authoritative.

### Structured Library projection integer compatibility

Before correction, invoking the actual `library::favourites` function against the production-style INTEGER owner schema failed with `error serializing parameter 0: cannot convert between the Rust type i64 and the Postgres type int4`. The same uncast ID fields could also panic during row serialization, and protocol query errors were silently treated as empty caches.

`library.rs` now fixes parameter types with `owner_user_id = $1::bigint` and equivalent folder parameters, keeping owner/folder columns indexable. Selected row and owner IDs explicitly cast to BIGINT for the Rust serializer. Fediverse row and protocol text decoding return errors instead of panicking or silently dropping wrong-typed rows. A missing optional protocol cache table still yields an empty section; other database/schema errors propagate to the canonical PHP fallback. Malformed cached JSON still follows the existing skip behavior. No content, saved flags, order, filtering, cursor, folder alias, or count projection semantics changed.
