# Settings AI alt-text panel native read (step S3, second part)

Rust paints the AI alt-text section on the Settings page (`?view=profile`): the configured / not configured status, the save form with the masked key field, the optional API base URL and model, and the Clear API key form when a key is saved. PHP keeps the shell, the session, `save_ai_key`, `clear_ai_key`, the key encryption and the rest of the page.

Only the key's presence is read. The worker selects `COALESCE(xai_api_key_enc,'') <> ''` and never the encrypted key; the reply carries `{panel: "ai_alt_text", configured: bool}` and the owner's own base URL and model in the form. The section is open to every active account, never admin-gated.

Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` plus `VAAK_SETTINGS_AI_NATIVE=1`, in both `www.conf` and `vaak.env`.

## What it does

`ap_settings_native_body('settings_ai', $viewerAdmin)` posts the usual envelope with offset 0 and `viewer_admin`. The worker requires the owner to exist, not be disabled and have exactly that admin role, before and after a READ ONLY transaction, then reads the owner's current `ap_users` row, as `ap_auth_user_has_xai_key` and the template's fresh `ap_auth_user_by_id` fallback do. The two forms carry the request's CSRF token, as the PHP section prints it.

One deliberate difference: if a save stores the key but the endpoint update then fails, PHP renders the page from the user row it loaded before the save, and the worker shows the stored state. Every successful save or clear refreshes PHP's row first, so both agree there.

Renders the PHP section instead when: the AI columns are missing (PHP shows not configured), printed text matches the `ap_fix_utf8` mojibake pattern that `h()` would repair, the account is unknown or disabled, its admin role changed, the session owner differs from the page owner, or anything else in the bridge refuses.

The Supporter reward form stays PHP. It is a static form behind `VAAK_SUPPORTER_CODES` with no per-account read, so there is nothing to project and moving it would only add an env flag the worker must mirror.

## Parity check

`api/bin/settings-ai-native-review.php` (sandbox only) renders the genuine section with the genuine `ap_auth_user_has_xai_key`, `ap_auth_user_by_id` and `h`, and compares whitespace-collapsed HTML for an admin with a key and padded, escaped base URL and model, an account with NULL columns, one with an empty key and only a base URL, and one with a key and only a model, in full and shell modes. The raw reply must never contain the encrypted key, the rows must report presence correctly, and the real bridge validator must accept each reply and reject an extra row key, a non-boolean presence, another panel name and a flipped role binding. Fallbacks: every case listed above, plus missing role and nonzero offset.

2026-10-20: 65/65 checks with INTEGER ids and 65/65 with BIGINT ids. The Second Life and WoW harness still passes 191/191.
