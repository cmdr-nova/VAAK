# Finite Library controller/native and saved-folder identity checkpoint

This checkpoint runs genuine password login, session/CSRF dispatch, Settings,
folder and subscription actions through the complete copied PHP controller. A
second controller prefers the actual serving Rust raw SQL collector and private
Library rendering endpoint. It compares significant complete fragment tokens
against the genuine PHP SQL/card baseline after each mutation. No policy helper
or canonical status mapper is substituted. Native canonical hydration is still
an open migration gate: this checkpoint uses the existing real PHP canonical
mapper to produce descriptors for the actual native handler.

A real accepted legacy event ID exposed a folder bug: bookmark storage resolved
it to a current canonical save key while folder membership stored the legacy
input. The controller returned Saved and count one, but the actual folder was
empty. New additions now store the same canonical key as bookmark storage.
Removal resolves owned saved keys and existing owned historical memberships.
Reads associate supported legacy cached identities without deleting history or
hydrating remote identities. Owner binding and current audience/deletion guards
remain authoritative.

The bounded historical associations are current saved keys, exact object URI
and its trailing-slash form, the old exact event namespace, event v2 IDs, and
old exact local IDs below two million. Historical local v2 timestamp validation,
v1 collision disambiguation, synthetic child IDs and other protocols remain
open. Matching IDs locate an already owned save; they do not grant an audience.
Multiple membership aliases for one saved row count and paint once. Unresolved
raw memberships remain stored and counted; counts need not equal currently
paintable cards. Distinct historical bookmark rows retain PHP's raw ordering and
cursor semantics; this phase does not silently merge those saves.

The final run passes the prior 28 whole-controller checks plus 88 checks over
26 PHP/native cohorts. Every cohort reaches the actual serving Rust SQL
collector (26 HTTP 200 responses); 21 private render calls return HTTP 200,
including empty batches after current mute/block filtering. Seventeen cards
are painted across the cohorts. Checks cover real sensitive-without-CW Settings
on/off, folder add/remove using legacy/current/URI/slash inputs, non-destructive
historical membership duplicates, raw offset one, foreign-owner membership
exclusion, current direct/deleted source rejection, Home deprioritization
preserving Library, subscriptions, actor trailing-slash mute/unmute and personal
domain blocking. Empty PHP collections and empty native batches do not by
themselves prove independent nonempty native moderation; earlier accepted
current-authority checks remain separate evidence.

The serving artifact is a fresh compiler output with profile.test=false, not a
test executable. Cargo used one job, offline/locked, worker only. The copied
543-path source manifest preserves byte hashes and modes before/copy/after;
production bytes still match it. Later fixture-only additions have their own
final receipts. Outbound DNS/connect/sendto are denied before wire by an owned
preload fixture; authentic curl loopback transport and PostgreSQL Unix socket
remain enabled. Cached media/actor facts are seeded. Cold media previously
reached the real disabled worker-nudge exec path; that failed boundary is
retained rather than claimed tested.

Reproduction: `python3 api/bin/library-controller-native-sapi.py` with the owned
PostgreSQL fixture cluster available. Exact compiler commands, immutable artifact
hash, fixture paths, retained failures and cleanup boundaries are in
`rust/target/parity-evidence/library-controller-native-phase/HANDOFF.md`.

Remaining gates include mixed Library native grant selection for historical
memberships (PHP safely falls back), complete native canonical/private child
hydration, full Bluesky variants, SQLite whole-controller execution, cold IO and
maximum-page performance. Relevant late-sensitive IO and remaining alias/domain
cohorts are not closed by this phase. No native rollout flags, live server,

review is required before acceptance.
