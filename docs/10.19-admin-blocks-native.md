# Admin Server blocks native read (step A6)

Rust paints the Admin > Server blocks body: the add-control form, the Blocked users and Blocked servers sections with their search filter script, and each row's Remove form and links. PHP keeps the shell, the session, the global CSRF injection, `block_add` / `unblock` and the ActivityPub Block/Undo deliveries.

Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` plus `VAAK_ADMIN_BLOCKS_NATIVE=1`, in both `www.conf` and `vaak.env`.

## What it does

Same envelope and protections as the other Admin pages (`view: "blocks"`, offset 0, no search). It reads `ap_blocks` newest first. `ap_block_list` now breaks created_at ties by id so PHP and Rust list same-second rows in the same order. Actor rows are labelled like `actor_display_name` / `actor_handle`: flat Redis actor cache first, then `remote_actors` (`profile_identity::lookup_actor`, which refreshes the flat cache the same way PHP does), then `profile_identity::label`. Relative times use the existing Admin helper.

An actor with no cached row or a placeholder username gets PHP's URL-derived label, and the worker queues the same async actor warm PHP queues (`profile_warm::actor_warm`: Redis lock plus `vaak:queue:ap_actor_warm`, PHP's process fallback otherwise), after the in-transaction admin recheck. The warms run concurrently so many misses share one Redis budget. Created_at may also be Postgres timestamptz text (`2026-10-19 12:00:00.123456+00`), which strtotime accepts.

Renders the PHP page instead when PHP would do something the worker does not: a local mkultra.monster / vaak.monster actor (PHP reads the local profile name), a non-https actor, an unknown scope, a created_at the helper can't parse, more than 1000 rows or a reply over the size bound, plus the usual non-admin, disabled/revoked admin and bad reply cases.

## Parity check

`api/bin/admin-blocks-native-review.php` (sandbox only) renders the genuine Blocks branch with the genuine label/handle/ensure/get/block-list declarations (file, Redis and warm-queue helpers stubbed, no Redis on either side) and compares whitespace-collapsed HTML. Each mode re-renders until PHP and the request share one clock second. Cases: empty; domains with escaping, "0"/null/multiline reasons, both timestamp formats and a same-second tie; actors with display names, empty and whitespace display names, a host override, a Bridgy Fed handle, a "0" display name, a numeric display name and a trailing-slash actor; and 170 mixed rows (both sections collapsed past 80). PHP queued no actor warm in any positive case. Fallbacks: uncached actor, placeholder actor, local actor, non-https actor, unknown scope, odd date, 1001 rows, ordinary user, disabled admin, revoked admin, wrong token, offset selector.

2026-10-19: 44/44 checks with INTEGER ids and 44/44 with BIGINT ids.

2026-10-19 follow-up: production showed 10 of 41 actor blocks with no cached actor, which made every request fall back. Uncached and placeholder actors are now positive parity cases ("warmed actors"), checked against the actor ids PHP queues and, with the optional queue Redis port argument, the ids the worker queued. 60/60 checks with INTEGER and BIGINT ids.
