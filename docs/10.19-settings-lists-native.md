# Settings personal lists native read (step S2, first part)

Rust paints three sections of the Settings page (`?view=profile`): Deprioritized on Home, Muted words and Your blocks, with their add forms and each row's remove form and links. PHP keeps the shell, the session, CSRF injection, every add/remove action, the Muted accounts section above them (actor names, avatars and custom emoji) and the filter script below them.

These are personal lists. Every account can use them, so the worker admits any active account and never checks for admin. Rows are always read for the session owner only.

Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` plus `VAAK_SETTINGS_LISTS_NATIVE=1`, in both `www.conf` and `vaak.env`.

## What it does

PHP's `ap_settings_native_lists_body()` posts the usual envelope to `/internal/admin/read` with `view: "settings_lists"`, offset 0, no search, and `viewer_admin`: whether the page shows the account as admin (it adds the "Admin → Server blocks" link). The worker requires that the owner exists, is not disabled and has exactly that admin role, before and after a READ ONLY transaction. It reads `ap_deprioritized_actors`, `ap_muted_words` and `ap_user_blocks` for the owner, newest first. `ap_deprioritized_list` now breaks created_at ties by actor id so both sides order same-second rows alike.

The bridge accepts only the closed row shape (`list`, `id`, `value`, `note`, `scope`, `kind`, `created_at`), checks the request binding including `viewer_admin`, then rechecks that the session user and their admin role are unchanged.

Renders the PHP sections instead when: the account is unknown or disabled, its admin role changed, any list has more than 1000 rows, a created_at the helper can't parse, a reply over the size bound, the session owner differs from the page owner, or anything else in the bridge refuses.

## Parity check

`api/bin/settings-lists-native-review.php` (sandbox only) renders the genuine three sections with the genuine list declarations and compares whitespace-collapsed HTML for an admin and an ordinary account, in full and shell modes. Each comparison re-renders until PHP and the request share one clock second. A third account's rows are seeded in every case and must never appear. Cases: empty; one row each; many rows with escaping, trailing-slash actors, same-second ties, "0" and empty notes/reasons, a "0" phrase, a future time, an empty time, both timestamp formats, an actor value with spaces and `~`, a domain block and an unknown scope. It also feeds each reply through the real bridge validator and checks it rejects an extra row key and a flipped role binding. Fallbacks: role mismatch both ways, unknown account, disabled account, wrong token, offset, missing role, search selector, role on an admin view, odd date, 1001 muted words.

2026-10-19: 111/111 checks with INTEGER ids and 111/111 with BIGINT ids.
