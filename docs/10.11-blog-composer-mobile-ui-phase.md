# Blog composer, mobile drawer, and post navigation UI phase

Implementation is staged locally. No commit, deployment, registration opening, or migration activation occurred.

## Changes

The Blog and DM fullscreen CSS hid the left rail after the mobile drawer rules had displayed it. A scoped override at the same existing mobile breakpoint restores the rail as a drawer on phones, including short landscape viewports, while keeping desktop fullscreen behavior.

The Blog composer now provides accessible buttons for the Markdown syntax already supported by the PHP renderer: bold, italic, three heading levels, bullet lists, and HTTPS links. Formatting works on selected text or the cursor, respects the content limit, returns the selection to the editor, and uses the browser's native insertion/undo command where supported (with a selection replacement fallback). Ctrl/Command+B, I, and K work in the content field. Delegated handlers also survive page replacement through soft navigation. Link editing never submits the publish form and rejects stale selection replacement. No preview or new Markdown syntax was introduced.

Actual submitted title, category, content, tags, and draft slug survive validation/storage/publishing errors. A newly saved draft whose publish step failed reuses its saved slug on retry. Null/empty success errors retain the original success behavior. The existing `blog_save` controller itself is byte-identical to Git HEAD (SHA256 `cb0dce88d46b269e2afad34ae78f3928edde9627c3010a2c040f77bf0eeed336`); this phase does not replace auth, draft storage, or publishing.

Post cards no longer repeat Open/Remote navigation outside their action menus. Existing owned and permission-aware menus retain their links and mutation controls. Guest/shared/raw cards, minimal notification and RSS fallback cards, list post cards, and queue post cards have a navigation-only overflow where needed. These menus add no mutation form. The raw Note link was moved to its equivalent Remote menu entry. Profile, collection/list navigation, report/policy references, and unavailable-quote recovery links stay intact.
