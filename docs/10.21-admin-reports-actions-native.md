# Admin moderation report actions native (step A10c)

The worker runs the four Moderation report actions: `report_note`, `report_dismiss`, `report_ignore` and `report_reopen`. PHP keeps the session, CSRF, the admin-only gate, the notice and error text, the filter it carries back to the page, and the page. It uses the `/internal/admin/action` route, bridge and reply from A10a (`10.21-admin-downranking-actions-native.md`).

Admin only. Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` plus `VAAK_ADMIN_REPORTS_ACTIONS_NATIVE=1`, in both `www.conf` and `vaak.env`. Other families' switches do not open this one.

## What it does

Copied from `ap_report_set_state` and `ap_report_append_admin_note`, inside a transaction that first reads the acting account `FOR SHARE` (an active admin with the actor key PHP sent):

- note: the note trimmed and cut to 5000 characters; an empty note or an id below 1 answers "Enter a note first."; a missing report answers "Report not found."; otherwise `[Y-m-d H:i:s UTC · handle]` and the note are appended to the trimmed history with a blank line between, and the history is kept to its last 50000 bytes.
- dismiss, ignore, reopen: the state set to `dismissed`, `ignored` or `open`; a missing report answers "Report not found"; a non-empty note is then appended as above, in the same transaction.

The signature is PHP's `$vaakHandle`, which the bridge sends as `admin_handle`. The worker derives the same value from the account row it holds (the trimmed username, or the actor key when that is empty, as `@name@mkultra.monster`) and accepts only that, so a note cannot be signed as someone else.

Outcomes: `note_saved`, `note_empty`, `note_report_not_found`, `state_set`, `report_not_found`. Nothing is cached for reports, so there is no after-save work.

Runs in PHP instead (the worker answers 422 before any write) when the note holds a NUL, the 50000 byte cut would land inside a character (PHP's update then fails and it reports that), a report id is past int4 on an INTEGER table (PHP's query raises), the handle does not match the account, the account is not an active admin with that actor key, or any query fails.

## Parity check

`api/bin/admin-reports-actions-native-review.php` (sandbox only) runs the genuine handler chain from `ap-admin.php` with the genuine report functions against a seeded PostgreSQL fixture. For each scenario it runs PHP with the switch off, reseeds, runs the native branch with PHP's handlers disabled, and compares the notice, error, view, carried filter and every report row (the note stamp's second normalized). It also checks the fallbacks write nothing and the bridge validator. Run the worker with `VAAK_ADMIN_REPORTS_ACTIONS_NATIVE=1`.

Scenarios cover notes on empty and existing histories, Unicode and HTML notes, the 5000 character cut, the 50000 byte history cap, empty notes, a zero id, missing reports, each state change with and without a note, reopening an open report, odd filters, and notes signed from a padded username, an empty username and a NULL username.

2026-10-21: 70/70 checks with INTEGER ids and 71/71 with BIGINT ids.
