# Search parity map and next executable slices

Mapping and staged implementation on October 10. Canonical PHP Search privacy corrections and an independent Rust ranked-candidate helper are now implemented; no native Search activation. Existing `search.rs` is a shadow projection with a lean serializer, not a completed replacement for PHP Search. Keeping `fallback=php` does not establish that projection results themselves match PHP.

## Current surfaces and ownership

| Surface | Canonical path | Behavior that must stay attached to this surface |
| --- | --- | --- |

| Shadow Rust | `/shadow/search-results` → `search::project` | Separate read-only contract; no PHP production Search caller currently consumes it |

## PHP source and state map

- Original baseline `admin_search_run` (ap-admin.php12111; corrected owner-key/current policy below): ASCII trim, limit1–40, offset0–160. Known HTTPS status URL returns an empty search bundle, while page routing owns opening/resolving that URL. Types are empty/all or statuses/accounts/hashtags. A fixed121-status/80-tag window is fetched once; account results are fetched separately. Fresh text page zero bypasses cache reads; later pages and repeated `#tag` clicks can read the `mf2` disk window. The cache key lowercases the query and includes resolve and fetch sizes, but no viewer. Current actor moderation is reapplied before status pagination.
- Original baseline `ap_masto_search` (ap-masto-entities.php9515; corrected owner-key/current policy below): UTF8 repair, ASCII trim, 200-character bound, type normalization, Redis cache keyed by lower query/type/resolve/limit. Bare instance queries suppress statuses/tags when type is all. Sanitizers run before cache write; endpoint owner filtering runs after cache read.
- `ap_search_fts_match_query` (ap-search-fts.php354): UTF8 repair, ASCII trim, lowercase **before** Unicode letter/number/underscore filtering, whitespace token split, prefix AND, up to8 tokens, minimum2characters. Explicit hashtag mode produces `htag_NAME OR NAME`. PostgreSQL tsquery conversion is distinct from SQLite FTS5.
- `ap_search_fts_query` / `ranked_hits` / `blend_networks`: incremental backfill/recent indexing hooks, limit180, **separate live Fedi and Bluesky queries**, current indexable opt-out with author exception, explicit `#tag` body filter, network-local rank/time order, then alternating streams beginning with the stronger first rank. Deleted mentions and absent live source rows are excluded before the ranked limit. The actual PostgreSQL generated-tsvector/GIN source is canonical; SQLite porter/unicode61 output is not a PG rank oracle.
- `ap_masto_search_statuses` (12683): UTF8 bound/tag detection; set-based hydration of status/mention/event IDs and cached Bsky URIs; Announce/Like remap to canonical live Create/Update; actual status builders; exact hashtag check on event/Bsky content; dedup. An underfilled FTS window can append a recent30-day Bsky full-query LIKE scan. Empty completed backfill is authoritative; otherwise canonical local/mention/event/Bsky LIKE fallback runs. This is not equivalent to unconditionally mixing a second AND-token cache stream into FTS ranks.
- Status builders are `ap_masto_status_from_row`536, `from_mention`4357, `from_event`7603, and `ap_masto_bsky_trend_status`; Search sanitization9627 unwraps Announce, canonicalizes object fragments, deduplicates IDs/URIs, normalizes required arrays/media metadata, and currently caps40. Web's121-window intent versus this sanitizer cap must be measured, not silently corrected in migration.
- Account builders are `admin_search_local_account`, `ap_masto_search_accounts`, actual local/remote account serializers, then account sanitizer9567. Web supports local host/typo paths, cached remote actor identity and optional explicit resolver; API adds following-only semantics. Web local ordering is ID ascending and local profiles provide names/avatar/preferences; Rust username sorting/lean account shape is a separate behavior.
- Hashtags use `ap_masto_search_hashtags`10166: bounded recent outbox400/events600/mentions300 corpus scans, per-occurrence Unicode hashtag extraction, substring query filter, descending counts, then actual tag entities. Rust's one cleaned query plus docs count is not this result list.
- `ap_search_*hidden/filter*` (ap-db.php11361–11618) is Search-specific actor/account policy: canonical aliases, current owner self exemption, personal/server actor/domain blocks/mutes and nested account/DID checks. It does **not** implement the complete Library audience/source/word admission gate. Web status rendering adds its own current policies. Test each surface before sharing admission helpers or claiming equivalent privacy.

## Proven observations versus pending repros

1. Actual PHP query normalizer returns `ix*` for `İX` and `ix* AND alpha*` for `İx alpha`. The original Rust functions returned `i` + combining-dot + `x*` for the former and retain that combining dot in the latter. The original Rust filtered before lowercase; the new helper follows PHP lowercase-before-filter ordering. Controls `１２`, NBSP-surrounded `foo`, and one-letter query otherwise agree in the sampled corpus. Commands/proof below.
2. Existing Rust projection uses one global FTS rank sort, omits canonical live-source EXISTS and hashtag body filter, then adds a differently tokenized Bsky LIKE stream and sorts combined ranks. These are direct source differences; the separately verified canonical ranked helper now preserves those rules, while the older shadow projection remains unpromoted.
3. Rust event/mention/local serializers hardcode public visibility, sensitive=false, empty CW, counts/actions/media/mentions/tags/polls/quotes; account serializers fabricate profile fields. Actual PHP builders retain these systems. No full parity claim can follow from merely matching Mastodon JSON key names.
4. Rust owner/event/mention/local/followed-tag lookups bind i64 against uncast ID/owner columns and use source_pk i64 row decoding. INTEGER compatibility must be exercised on actual `project`, not only extracted SQL. Candidate/source errors are often converted to missing hits, and Bsky errors become empty results; distinguish genuine optional caches from schema/type defects.
5. Independent actual PHP cached-bundle/full-painter controls proved shared author-exception leakage and reverse author omission, indexable withdrawal, audience/follower/direct revocation, local deletion, nested private quotes, nested actor moderation and private/deleted-only hashtag discovery. The authorized corrections use owner-separated web/API cache keys and fresh durable Search source checks. Search intentionally retains word-muted results. See the current contract below.

## Minimal independently testable implementation slices

### 0. Canonical capture and privacy baseline (first, parallel with slice1)

Ownership: capture/UI agent owns new `api/bin/search-reference-capture.php`, `search-current-policy-postgres.py`, `search-cache-surface-php.php` and surface ledger. No runtime edits initially. Use actual PHP helper extraction and actual PDO PostgreSQL extension against a fresh disposable database/schema. Use real mbstring. Instrument network/async boundaries explicitly; expected output must come from PHP, never generated native output.

Capture web/API query/type/resolve/limit/offset/heading/fragment/has-more/following. Exercise warm mf2 and Redis responses under ownerA/B/self, indexable and discoverable edits, private/direct/local/public audience, deletion, mute/block and word changes, nested quotes/boosts, malformed source. Check actual final HTML as well as returned bundles and actual v1/v2 API output. Test both cache cold and cache warm; preserve current policy and classify any deliberately authorized privacy correction separately. Known remote resolve/URL IO remains canonical PHP until the adapter is proven.

### 1. Native query and ranked candidate parity (next implementation slice)

Ownership: native query agent owns `rust/vaak-worker/src/search.rs` query path and new `search_query.rs` / `search_ranked.rs`, plus `api/bin/search-ranked-postgres-fixture.py` and `search-ranked-php-postgres.php`. Do not promote lean serialized statuses/accounts or change PHP caller/UI in this slice.

Gate1A: actual normalizer differential corpus (Turkish dotted I, Greek sigma, accents, decomposed combining marks, fullwidth digits, CJK, NBSP/thin-space, invalid UTF8 repaired at PHP request boundary, escaped `%/_`, operators, tag minimum/length and 200-character bounds). Rust's str cannot represent invalid bytes; the adapter must define validated UTF8/normalization responsibility explicitly.

Gate1B: INTEGER and BIGINT actual `search::project`/ranked helper calls on production table fields, not SQL-only wrappers. Compare actual `ap_search_fts_ranked_hits` and `blend_networks` in the same DB: tied ranks/times, separate stream alternating, missing/deleted sources, owner indexable exception, explicit tag precision, 180ranked cap and underfill windows, NULL object/time fields, current preference edits without reindex. Preserve integer indexes with explicit parameter casts and selected numeric casts, checked EXPLAIN. Test missing optional Bsky cache versus bad schema/type errors.

Gate1C: FTS available/unavailable/incomplete/done states, recent indexing hooks and set-based hydration boundary. For an unimplemented backfill/LIKE branch return an explicit whole-request PHP fallback; never silently claim an empty authoritative result. Candidate-only parity must expose candidate provenance and stop before final result serialization.

### 2. Search source hydration and serialization parity

Ownership: dedicated source/serialization agent owns new `search_source.rs`, `search_context.rs`, `search_status.rs`, `search_account.rs` and actual full-entity fixtures; capture/UI keeps canonical expectations. Preserve complete AS2/PostView/FeedView/current local rows, live canonical event remap, fresh owner actions/avatar/profile/privacy/CW/counts/polls/Ask/quote, IDs and original source aliases. Reuse Library pure painters/current fact helpers only for verified matching semantics; remote cold source/actor, signed fetch, OG, unresolved embeds remain explicit whole-request PHP fallback. Independently verify quote/reblog wrapper policy and late source admission. Match sanitizers including dedup and deliberate caps before pagination.

### 3. Accounts and hashtags

Ownership: separate small source slices or serialization agent, each with an independent actual PHP fixture gate. Web local host/mask/typo and SQL ordering/current profile vs remote host/handle/resolve; API full account shape/discoverability/numeric-user filtering/following. Hashtags need bounded canonical corpus scans, occurrence counts, substring filters, tag entity/follow state and all results—not a synthetic single query tag. Keep explicit external resolution and IO on PHP until actual budget/redirect parity is proven.

### 4. Cache and surface integration (last, default off)

Ownership: capture/UI agent plus coordinator. Preserve current fixed windows, cache TTL/key/fresh-page behavior, source/budget/IO/URL/query flags, owner re-filtering, filtered-row offsets and has-more, and API v1/v2/following semantics. Introduce an authenticated server-owned batch/request boundary only after preceding gates; no browser owner/role/facts authority. All-or-nothing PHP fallback on the same assembled source window; no extra enrichment on retry, no partial cards, no default-on switch. Genuine CURL/PDO surface comparisons and final independent verification precede any activation proposal.

## Implemented query slice and current privacy contract

The Rust `ranked_candidates` helper matches actual PHP `ap_search_fts_ranked_hits` plus `blend_networks` against the same PostgreSQL database, on INTEGER and BIGINT schemas. Fixtures compare actual rows, rank values and stream order, current indexable author exception, absent live rows, deleted mentions, explicit hashtag underscore escaping, current source deletion and the 180-result bound. PostgreSQL float4 rank is converted through its shortest decimal representation to match PDO's canonical JSON numeric value. Equal rank/time ties remain unspecified by the original SQL. Missing cache/schema/query errors are explicit PHP fallback boundaries; FTS backfill, underfilled LIKE hydration and the old lean serializer are not promoted.

`search-query-reference.php` supplies actual PHP Unicode expectations to the Rust unit test, including contextual Greek final sigma and the different lowercase/filter order in text versus explicit hashtag mode. Invalid UTF8 remains repaired by the canonical PHP request boundary; a Rust `str` is not evidence of invalid-byte parity.

Canonical `ap_search_status_allowed(status, owner, depth, currentLocalRows)` is now the Search-specific durable predicate. It checks current local note existence, current AT post cache existence, or the latest known remote event/mention source. Latest Delete/Tombstone/deleted rows deny. Current local indexability has the original author exception. Canonical audience checks and existing actor block/mute checks apply recursively to full displayed sources. Search does not apply word mutes. A quote descriptor with state pending/accepted/fallback and no URI/account/body/media is harmless presentation metadata and is allowed; any actual recovered child must pass the final painter gate.

`admin_search_render_context_allowed` runs after canonical enrichment and before any Search card HTML. It binds recovered full quote children and compact preview authorities from canonical policy maps/current cached lookup, and owner-proven RSS rows. Unknown body-bearing preview authority fails closed. This is a Search-only hunk; other return views retain their existing policy.

Web disk windows now use owner-separated `mf3` keys. API Redis keys include the authenticated owner. Both reapply current source admission on hits before output/pagination, and current permitted hashtag rows are recounted instead of accepting source-less cached tag entities. API bare-host all-type queries still return accounts only. Outbox/event/mention hashtag scans retain their bounded 400/600/300 row and count-order semantics and use narrow source fields; remote rows are checked against the latest object state before ingestion.

Independent fixtures are `search-cache-privacy-independent.php` and `search-privacy-postgres-independent.php`; the latter exercises actual canonical guards and final painter against genuine PDO PostgreSQL on both ID widths. The affected existing `library-moderation-actions-smoke.php` remains green (90 actual controller/writer/warm-policy controls). Search source normalization, API/full surface integration, authenticated native rendering, cursor/browser behavior and complete serializers still require their own gates.
