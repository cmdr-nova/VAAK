# PHP reference contract for the next Rust migration

Date: October 10, 2026. Scope: Library rendering, Search integration, remote profiles and post detail. This is a migration acceptance contract, **not a declaration of 100% parity**. The existing PHP implementation is the behavioral reference. Preserve working functionality, saved settings, permissions and actions; investigate suspected privacy defects separately rather than silently copying or changing them during migration.

## Release rule

Do not enable a native replacement until all relevant rows below have executable PHP/Rust differential coverage, independent expected privacy assertions, isolated database/action checks and browser integration checks. Shape tests, advertised capability names, Rust serving PHP HTML and partial reference functions are useful evidence but do not establish full native parity. Missing parity means keeping the working PHP path for that capability and accurately describing the boundary.

No production account writes, federation, external delivery or credentials are needed to build the test corpus. Production rollout and full parity sign-off remain separate from this discovery document.

## Search acceptance matrix

* Query modes: all/accounts/statuses/hashtags, empty/whitespace, Unicode, escaped punctuation, hashtag query, partial text, full URL and local-host typo/account normalization. Resolve flag, section, offset, limit and URL state must survive soft navigation and append.
* `admin_search_run` uses a ranked window of 121 statuses and80 tags, caps offset at160 and limit at40. New text query stays fresh; later pages and hashtag clicks may reuse shared disk bundle (default45s), then owner filtering happens **after cache read**, before slicing. Accounts use their own pagination. Replacing this with SQL offset filtering changes the result window; prove compatibility explicitly.
* Existing FTS indexable filtering, local author exception, deleted rows, source ordering, network blend, deduplication, query token normalization and fallback when FTS is unavailable need actual PostgreSQL differential fixtures. SQLite tests cannot establish production SQL parity.
* Preserve full hydrated status metadata: visibility, spoiler text, sensitivity, attachments, quoted/reblogged content, owner interaction state and normalized author. Rust must not hardcode public/nonsensitive/empty-CW values. A source hit is not permission to display that source.
* Account discoverability/indexability and block/mute alias behavior require distinct fixtures. A public actor opting out of discovery does not mean an explicit URL lookup is forbidden; follow PHP's surface-specific rules.
* URL status search currently returns an empty orchestration bundle for controller redirect/resolution. Preserve exact redirect, target normalization, permitted fetch, failure message and navigation behavior; no native remote network writes during shadow reads.
* Section summary/count labels, per-section has-more, empty results, result account buttons/relationship state, hashtag links and full status cards must match. Existing `search-parity-smoke.php` checks a projection/manifest, not all these outcomes.

## Remote profile and post detail acceptance matrix

* Profiles include ActivityPub, Bluesky and local identities, aliases/WebFinger, cached metadata, explicit fallback recovery, avatar/header/bio/fields/verified links/badges, follow/follows-you/request state, stats including combined-network stats and profile links. Preserve Phyrian/OpenSim badges/bridge information and viewer-specific permission to act.
* Profile tabs include posts/replies/boosts/media/asks/pinned/featured/blog where present. Respect saved hide-profile-replies/boosts with unavailable-tab fallback to posts; empty pinned/featured/blog behavior; AT reply vs repost vs quote classification; published asks and owned content; dedupe crossposts. Secondary tabs must not trigger unnecessary full author-feed hydration.
* Full/partial profile routes, pretty local paths, tab/from query state, pagination, pinned order and empty/error/blocked presentation must match. Direct profile access deliberately differs from timeline discovery: PHP content-block checks allow a personally muted author to remain explicitly viewable. Do not apply Home suppression wholesale.
* Post detail handles RSS mirrors redirecting to article/RSS, Fedi URL and synthetic fragments, `bsky:` and `at://` normalization, Bluesky gallery repair, cached/local/ask/remote lookup, deleted/missing/blocked posts, focused card, ancestors/descendants and partial thread loading. Exact ordering, cycle/dedupe limits and all child audience grants matter.
* Threads explicitly exclude blocked accounts while a mute alone still permits thread content (`:31487`). Nested quoted/boosted content may follow other policies. Record each actual caller policy instead of inventing one generic rule.
* Detail/profile back links preserve `from` semantics and existing labels; compose reply/quote/edit/delete/report/block/mute/follow/ask and gallery/poll actions retain current IDs and behavior.

## Offline reference harness and verification status

`php api/bin/migration-php-reference-smoke.php` currently executes selected **actual PHP function declarations** extracted with PHP tokenization. It does not bootstrap `ap-admin.php`, load production configuration, make HTTP requests, use Redis or connect to a database. It currently passes37 checks covering thin/enrich ID/flags/budget, bookmark envelopes, AT conversion, recursive moderation, public nested visibility, per-owner settings distinction, and durable-audience failure/deletion/recipient decisions against controlled database boundary stubs.

`php api/bin/migration-php-reference-smoke.php --json` emits deterministic actual-PHP bookmark envelope HTML for native differential consumption. Card functions in this harness are intentionally identifiable fixture stubs. Database policy answers are fixtures rather than SQL execution. These tests **do not establish full card rendering, PostgreSQL grants, mutation execution, browser behavior or complete PHP/Rust parity**.

`php api/bin/migration-folder-reference-smoke.php` additionally passes57 checks executing actual folder declarations and SQL against a disposable in-memory SQLite database. It validates persisted owner isolation, title trimming/Unicode limit, duplicate membership, bookmark creation, membership removal, folder deletion retaining bookmarks, cross-folder unbookmark cleanup and the40-folder cap. The underlying bookmark insert is a fixture transport; this does not test the authenticated controller, remote delivery, Redis invalidation or PostgreSQL query behavior. `migration-reference-functions.php` supplies reusable declaration extraction for both harnesses.

The full Mastodon card alone is1055 lines and calls roughly75 feature helpers (including quote hydration, asks, polls, action state, media/CW, link previews and own-post action bars). A valid renderer harness must load those actual painters and predicates, and fake only external IO and deterministic transport/time/session values. Stubbing the feature helpers would erase precisely the compatibility evidence this migration needs. Dedicated Bluesky/RSS painters must be captured separately rather than inferred from this card.

`php api/bin/migration-card-reference-capture.php > /tmp/vaak-card-capture.json` captures **37 actual renderer/admission contexts**. It loads actual Library/Mastodon/Bluesky/RSS painters, admin feature helpers, saved-profile getter, saved-interaction SQL predicates, recursive moderation and durable-audience predicates. The fixture database is disposable SQLite; source bootstrap never runs and HTTP/HTTPS streams are disabled.

The corpus includes plain/CW/media/boost/quote/private cards; own edit/delete/pin forms; Ask cards; open multiple-choice, voted and expired polls; previews; current saved sensitive preference on/off with explicit CW retained; saved fav/bookmark/boost undo state; owner RSS lookup/normalization; normalized Bluesky, labels and legacy fallback; direct-delivery grants; denied block/phrase/private/direct/deleted/foreign-RSS/native-DID/nested-DID cases; cached recovered quote allowance and revoked/deleted/blocked quote denial. Four sequential preview failures assert the real renderer's budget of three synchronous requests and four background warm requests.

Each capture exports `status`, `expected_admitted`, `context` and actual `html`. Authoritative context includes authenticated owner/actor/key, current full profile, durable interaction rows, local status/poll/RSS rows, Ask metadata, CSRF value, resolved avatar, current event/outbox/following audience rows, current personal/server/native-DID moderation rows, recovered cached status snapshots and recorded preview transport requests/budget. Native implementations must consume these inputs; deriving permissions from expected HTML or fixture names would invalidate the comparison.

Transport substitutions are explicit: fixture session/CSRF and database; pre-provisioned tables/index DDL compatibility; moderation cache/list transports reading current fixture database rows; cached status resolver reading fixture snapshot JSON; preview HTTP failure and background queue recording. **Actual decision predicates execute** against those values. The direct delivery/following/private fixtures compare independently expected allow/deny outcomes. This still does not verify real PostgreSQL schema/migrations, actual Redis cache invalidation, signed remote fetch/proxy behavior, every media/Ask/poll/own-post feature branch, controller CSRF/authentication/authorization, mutation persistence/delivery, all other pages or browser behavior. Rendered action forms do not establish permission to execute those actions.

A concrete correction is deliberately separated from the compatibility baseline: the prior saved-Library ingress did not invoke durable audience/recursive moderation checks, and raw cached fragment responses could skip fresh admission. The current reference includes explicit guards, owner RSS refusal and late recovered quote checks from the independent privacy fix. These are privacy corrections with independent denial assertions, not an attempt to preserve leaked data. The independent `php api/bin/library-privacy-admission-smoke.php` covers those cases with its own SQLite admission fixtures.

One legacy behavior is recorded without silently changing it: malformed Bluesky author metadata that forces the dedicated fallback painter yields `return_view=bluesky` despite a Bookmarks caller. Preserve this captured baseline until a separately explained/tested correction is authorized. Relative timestamps use execution time; native tests should share fixture timestamps or normalize only the time field. No transport stub always grants admission and no painter is stubbed in the card capture.

Next evidence gates:

1. Build an isolated PostgreSQL/Redis dataset with users A/B, all audience/moderation/settings cases, mixed network interactions, folders, RSS and equal timestamps. Run actual PHP queries/helper dependencies and Rust against the same reset snapshots, compare ordered keys/cursors and canonical payloads.
2. Add full real PHP card renderer execution in a fixture-only bootstrap. Capture DOM structure, form actions/hidden IDs, viewer affordances, sensitivity state and media links. Do not compare only screenshots or stubbed HTML. Compare Rust native cards or explicitly retain PHP ownership.
3. Run mutation fixtures through the actual authenticated/CSRF controller using local test sessions, transactional/reset database state and fake delivery transports. Compare durable tables, queue payloads, cache invalidations and response/UI state, not merely declared write ownership.
4. Run browser tests for first paint, infinite scroll, folder picker, soft navigation/back state, all displayed actions, failed requests and privacy-setting changes after cache warm. Compare full PHP baseline with candidate; no live production mutations.
5. Keep a case-by-case coverage ledger: reference captured / differential passed / independent privacy assertion passed / action/browser passed. Any missing case blocks that capability's replacement. Changes correcting genuine PHP bugs must have separately stated before/after expectations.

No claim of100% parity or approved production switch is made by this document.
