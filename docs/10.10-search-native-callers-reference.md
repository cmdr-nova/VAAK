## Explicit dependencies and scope

The actual card corpus supplies real mbstring, function extraction without application bootstrap, current fixture owner ID 1/actor `fixture`, trusted CSRF `fixture-csrf-token`, clock capture and provisioned PDO tables. Each window restores its SQL saved/local/poll/moderation/audience/follow/quote-cache/Bsky rows, profile auto-unblur and request memo/global state before each paint. Actual `ap_following_list`, alias membership and `ap_following_id_set` run against production-shaped fixture following rows; current following is not supplied as an expected badge.

Inherited transports are disclosed: cached status lookup reads `fixture_status_cache`; moderation fetch functions read their provisioned fixture tables; external HTTP stream wrappers are removed; preview HTTP records requests and returns no fetched HTML, while warm requests are recorded; graph migration/bootstrap DDL is replaced by fixture provisioning. These are source/IO boundaries, not always-allow painter or policy stubs. The real Search admission and visibility helpers execute against current PDO state, including the positive and negative local audience controls.

Tag following is already a supplied canonical collector field at this PHP caller boundary. Its DB-backed native resolver is proved by the separate component fixture, not by this capture. Numeric account-ID aliases, connected Bsky graph/cache precedence, unsupported native source admission and owner switching likewise retain their separate component/context gates. This capture does not pretend to cover those systems through its ordinary account cards.

No real user session, full SAPI authentication, deployed routing, server headers, PHP POST action execution, HTTP bridge secret/serialization/body limits, native batch fallback or browser integration is tested here. Existing inspected session gate restricts guest access to remote profiles; this fixture simply binds an authenticated-shaped owner for painter execution. Actual browser Search pagination is documented separately in `10.10-search-loader-browser-review.md`. Runtime wiring, default-off flags, malformed UTF-8 transport checks and before/after native comparisons remain outstanding integration work. No runtime files, activation, production data, commits or deployment were changed.
