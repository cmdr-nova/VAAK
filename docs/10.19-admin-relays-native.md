# Admin Relays native read (step A3)

Rust paints the Admin > Relays body. PHP keeps the shell, the session, the CSRF value and every relay action (add, enable, disable, remove), and the relay Follow/Undo deliveries.

Default off. It needs all three:

- `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` (the existing Admin read switch, shared with Invites and Approvals)
- `VAAK_ADMIN_RELAYS_NATIVE=1`

Set them in both `www.conf` (PHP-FPM) and `vaak.env` (worker), like the Users switch.

## What it does

`ap_admin_native_read_body('relays')` posts the usual Admin read envelope (`view: "relays"`, offset 0, no search) to `/internal/admin/read`. The worker checks the current active admin before and after a READ ONLY transaction, reads `ap_relays` ordered by id, and paints the same counts, add form, per-relay badge, follow id, updated time and the Enable / Retry Enable / Cancel / Disable / Remove forms with the session CSRF. The PHP bridge rechecks the reply shape, the request binding and the current admin before using it.

Falls back to the PHP page on: switch off, non-admin, disabled or revoked admin, more than 100 relays, any malformed reply or transport error.

## Parity check

`api/bin/admin-relays-native-review.php` (sandbox only; refuses a database without "fixture" in its name) renders the genuine Relays branch from `ap-admin.php` against seeded PostgreSQL and compares it with the worker reply after collapsing whitespace runs. Cases: empty, one accepted relay, all states plus an unknown state, empty/"0"/null follow ids, escaping in URL, follow id and timestamp, in full and shell mode. Fallbacks: ordinary user, disabled admin, revoked admin, wrong token, offset and search selectors, 101 relays.

2026-10-19: 31/31 checks with INTEGER ids and 31/31 with BIGINT ids. The bridge accepts the reply and refuses extra row keys, a null inbox URL and a wrong binding.
