# Settings Second Life and World of Warcraft panels native read (step S3, first part)

Rust paints the Second Life avatar and World of Warcraft character panels on the Settings page (`?view=profile`): the linked card with its unlink form, or the pending-code verify form and the start form, and the Armory link form. PHP keeps the shell, the session, CSRF injection, the in-world IM, the code check, every link/unlink action and the rest of the page.

These are personal panels. Every account can use them, so the worker admits any active account and never checks for admin, the same way as `10.19-settings-lists-native.md`. Rows are read for the session owner only. The challenge query selects the username, agent id and expiry; the code hash and attempt count are never read.

Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` plus `VAAK_SETTINGS_LINKS_NATIVE=1`, in both `www.conf` and `vaak.env`.

## What it does

`ap_settings_native_body('settings_links', $viewerAdmin)` posts the usual envelope with offset 0 and `viewer_admin`. The worker requires the owner to exist, not be disabled and have exactly that admin role, before and after a READ ONLY transaction.

- Second Life: `ap_sl_links` for the owner. With no link, the newest `ap_sl_challenges` row whose `expires_at` is at or after `gmdate('c')`, compared as text exactly as PHP binds it. The profile link follows `ap_sl_profile_url` (trimmed, lowercased UUID, else `https://secondlife.com/`).
- World of Warcraft: `ap_wow_links` for the owner.

Rows are `{panel, state}` for `second_life` (`linked`, `pending` or `unlinked`) then `wow` (`linked` or `unlinked`). The bridge accepts exactly that order and those states, checks the request binding including `viewer_admin`, then rechecks that the session user and their admin role are unchanged.

Renders the PHP panels instead when: a table is missing (PHP catches and shows the unlinked panel), printed text matches the `ap_fix_utf8` mojibake pattern that `h()` would repair, a verified or expiry date the helper can't parse (PHP prints it raw), the account is unknown or disabled, its admin role changed, the session owner differs from the page owner, or anything else in the bridge refuses.

## Parity check

`api/bin/settings-links-native-review.php` (sandbox only) renders the genuine panel region with the genuine `ap_sl_*`, `ap_wow_*`, `h` and `relative_time` helpers and the production table definitions, and compares whitespace-collapsed HTML for an admin and two ordinary accounts, in full and shell modes, across empty, linked, pending (newest of two live challenges wins, expired ignored), image-less and space-format-expiry cases. A fourth account's rows and every code hash are seeded and must never appear. The rows must name the right states, and the real bridge validator must accept each reply and reject an extra row key, a pending WoW state, swapped panels and a flipped role binding. Fallbacks: every case listed above, plus missing role and nonzero offset.

2026-10-20: 191/191 checks with INTEGER ids and 191/191 with BIGINT ids.
