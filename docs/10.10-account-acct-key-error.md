# Account-key PDO error cleanup

`ap_masto_remote_account_acct_key(actorId)` contained an unrelated followed-tags cache assignment in its caught account lookup error path. It referenced an undefined owner variable even though the function only accepts an actor URL. A real PDO preparation error therefore warned and mutated the followed-tags cache at an empty key.

The correction removes that one assignment. The existing catch still ignores the account-cache error and continues through the same path fallback. It does not change the legacy PHP path regex, username placeholder rules, host selection or Unicode lowercase behavior.

`api/bin/account-acct-key-error-smoke.php` executes the actual extracted helper with real SQLite PDO. Preparing the actual remote-account query against an absent table throws a genuine PDO exception; no policy or PDO method is stubbed. A saved pre-edit source at `/tmp/vaak-account-acct-key-before.php` reproduces five undefined-owner warnings and the unrelated cache mutation (four before assertions). The candidate passes six checks for genuine query failure, no warnings, unchanged owner tag caches, exact canonical path/numeric/HTTP/query fallback values and a successful actual cached-account lookup. The existing regex quirks, including `/usersAlice` versus `/users/Alice` and the query-bearing `@` fallback, are intentionally retained.
