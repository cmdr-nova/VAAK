Profile identity and source branches must remain distinct. AP `/@name` first tries cached `/users/name`, then canonical resolver/WebFinger, then queues warm; arbitrary references use `ap_resolve_actor_ref`. Cached aliases may select the IRI holding actual events. AP headers use flat/PG metadata and cached avatar/header, with source URL and avatar-header fallbacks. Missing/placeholder/stale metadata, metadata older than 12 hours and explicit refresh queue background warming. Missing media slots queue media warming. Full paint does not synchronously fetch an AS2 actor document; identity resolution is a separate possible IO boundary.

Bluesky uses owner-scoped profile cache plus queued actor refresh, AT DID/handle canonicalization and cached viewer `following/followedBy` with durable graph fallback. It requires a connected session; the baseline otherwise produces its existing connect-account error. Only posts/replies/boosts/media queue author-feed refresh and load up to 40 cached rows. Repost reasons go to boosts, ordinary replies to replies, quotes remain posts; images/video/recordWithMedia also populate media. Preserve existing owner-linked native rows, crosspost/fediverseId/mirror dedupe and protocol-specific interaction IDs.

Local headers use current `actor_profile`, not remote actor/media metadata: safe HTTPS avatar/header, plain bio, emoji display, PropertyValue fields with verified-at indicators, configured badges, Second Life/WoW links and Phyrian/OpenSim Resonant badge (`:32998`). Combined counts use `ap_profile_combined_follow_counts(...,false)` without synchronous remote refresh. Header Posts excludes replies and boosts and uses the existing max comparison with available Bluesky count; it is not a simple sum. Owner/nonowner follower/following links differ.

Local-only tabs are pinned/posts/replies/boosts/media/asks/featured/blog. `ap_profile_order_tabs` (`ap-profile-html.php:12`) defines order. Current hide-profile-replies/boosts remove tabs and redirect an explicitly requested hidden tab to posts. Empty pinned/featured/blog also fall back to posts. Pinned count is bounded to 5; full cards hydrate only on pinned. Featured count avoids remote-avatar/card work until featured; blog count avoids the list until blog (40 published posts), and sanitized `post` slug selects a published post. Answered Ask list is owner-scoped and bounded to 200, with current source/identity rendering; other tabs query only its count. The raw requested tab controls preload decisions before effective-tab fallback, which must be included in differential tests. Selected secondary tabs must not trigger unnecessary author-feed hydration.

Relationships use indexed owner/target trailing-slash lookups rather than rebuilding whole follow graphs (`:32890`). Preserve following/mutual/follows-you, locked local approval/pending cancel, owner state, post subscription, guest remote-follow address form, and current CSRF/session permissions. Header actions include follow/unfollow/cancel, local subscribe/unsubscribe, local mention, account bite, personal block/mute/deprioritize and admin block actions, protocol-specific open/follow-on-instance links. Card actions retain reply/quote, favourite/reblog/bookmark/folders, poll, edit/delete/pin, report/DM and exact actor/from return values. Profile action targets are rebuilt in shared painting (`:17947`); status return view has its existing `from=search` action-base quirk. Existing PHP action handlers remain authoritative during read migration.

Settings acceptance covers current manually-approves, media auto-unblur, hide-profile tabs, automated badges, reply/quote policy, incoming `asks_enabled`, indexing/discovery and collection consent, plus webmentions and deletion/retention invalidation. Collection membership/import consent (`ap-collections.php:595`) is distinct from the local Featured endorsements list (`ap-featured.php`); do not invent a Collections profile tab or hide explicit normal ActivityPub lookup because discoverable/indexable is disabled. Published answered Asks differ from incoming-Ask permission; `ap_ask_store_inbound` (`ap-asks.php:488`) checks the setting. Current profile header does not itself prove all Ask-send UI/action paths.

Direct access uses `ap_actor_is_content_blocked` (`ap-db.php:11346`): personal/server blocks restrict content, while personal mutes, muted words and server kind=mute do not impose timeline discovery suppression. Guest must still get public-only content and no owner actions. Each root and every displayed quote/reblog/parent/reply needs current durable audience and deletion checks. Subsequent actual provider/controller probes established a reachable PHP detail audience defect; the candidate now has final `admin_direct_status_allowed` / `admin_direct_render_context_allowed` gates and passes the 306-control INTEGER/BIGINT reference in `10.10-remote-profile-policy-reference.md`. Direct scope is selected independently from the action return origin using focused status, status/remote_profile return view or actual status route. `10.10-remote-direct-context-reference.md` records 794 actual complete PHP presentation captures and the proposed private native contract, plus measured partial root-block and full refresh differences; it certifies no native direct migration. Nested quote moderation also retains the actual saved-origin Library exception. Do not copy Library word-mute policy into a new direct-surface proof token.

Detail preserves owner-bound RSS mirror→HTTPS article/RSS redirect; `bsky:`/`at://` to web URL; interaction-fragment stripping and AP URL candidates; any local actor's note identity; Wafrn Ask mention projection; cached event then bounded remote ensure/repair; account-bite/no-associated-post and deleted-local/missing-remote messages. Bluesky focus allows gallery/AppView repair budget 2 and prefers mapped local parent where appropriate. Initial context walk is cache-only, ancestor depth 20; partial allows fetch, depth 12 and remote context up to 40. Reply-only polls skip focus re-ensure, ensure at most 5 missing Notes with 4-second timeout. Context has local child limit 50, mention limits 80/40, DM branch up to 200 (with mark-read side effect); preserve classification, dedupe and chronological order, cycles and bounds. Full refresh_thread permits sync context refresh. Browser keeps focus stable, aborts on leaving/hidden state, starts reply poll at 20 seconds then every 45 seconds, and merges by source identity.

Two concrete baseline discrepancies must be measured, not silently guessed away. `ap_local_profile_tab_page` assigns all nonempty in_reply_to rows to Replies; existing Rust `fetch_outbox_tab` and the preliminary full PHP bucket keep self-replies in Posts. Current full local four-tab fallback calls the same PHP producer as append, so that preliminary bucket does not determine final local AP cards. Bucket self detection still references the signed-in owner; conditional linked-Bluesky merge/preload and bucket fallback remain separate required comparisons. Existing Rust `hidden::status_hidden_on_profile` exempts only root personal mute while applying nested mutes and muted words; direct PHP content-block checks do not establish that exact behavior. Neither is settled by module comments or prior lean-path tests.

After Search closes, the smallest verifiable implementation slice is a default-off typed direct-surface context plus complete cached AP/local profile card rendering, leaving the PHP header/shell/actions intact. First build actual PHP differential fixtures for current root and nested audience, deletion, guest, block-versus-mute behavior and self-reply classification against INTEGER/BIGINT PostgreSQL, with mandatory supported cards and explicit whole-request fallback for unresolved recovery. Then replace the local four-tab lean paint through a verified internal producer/caller contract, including complete shared card forms and header/cursor preservation. Header/metadata/relationship and secondary-tab migration follows with separate bounded-IO gates; Bsky and complete detail threads are later explicit slices. No activation should follow solely from lean HTML success.
