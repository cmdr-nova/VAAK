# Independent Library card review

October 10, 2026. This records a development review, not migration approval.

The candidate lives in `library_card.rs`, `library_actions.rs`,
`library_body.rs` and `library_context.rs`. No native full-card route or PHP
cutover invokes it yet. Missing branches return errors rather than substituting
lean cards. This is the right development behavior; a later controller must
fall back to canonical PHP for the whole affected card/page, preserving source
pagination, rather than treating these errors as permission to omit cards.

## Independent reference coverage

`api/bin/php-policy-test api/bin/library-card-independent-capture.php` captures
22 combinations through actual canonical PHP painters and decision helpers.
It imports the canonical fixture's disposable SQLite/session/cache transports,
but does not replace painters, permission decisions or action HTML. Cases cover
Favourites return context, escaping, numeric/string counters and flags, missing
identity/date metadata, boost metadata fallbacks, CW with video/audio/poll/quote,
custom CW combined with sensitive auto-unblur, numeric IDs, negative counters,
HTML5 entities, empty-body sensitivity and lazy bookmark image/video loading.
Native differential coverage must explicitly require supported combinations;
silently ignoring `Err` results only demonstrates the subset that rendered.

The review found PHP scalar-coercion mismatches in the first native candidate:
JSON string counts/flags and numeric IDs. These were reported to the native
implementation owner. It also found an invalid PHP regex delimiter inside
`admin_reply_mention_handle` that emitted a warning on missing-acct fallback;
this was reported separately as a canonical bug rather than silently copied.

## Browser evidence

`python3 api/bin/library-card-browser-fixture.py` builds a local browser fixture
using exact existing engagement, poll and capture-phase CSRF handlers. Its fetch
transport is fake and CSP prevents external resource loading. Real Chromium
passed 14 checks on canonical PHP cards: CSRF injection and exact IDs, failure
rollback, success toggle, bookmark-folder picker instead of immediate removal,
closed/open CW, saved auto-unblur with custom CW retained, rejecting empty poll
selection, preserving vote/CSRF fields, avatar tooltip suppression and hover
identity preservation. This establishes client behavior with
the reference markup, not real PHP authorization or persisted/federated writes.

The builder accepts `--native captures.json` with identical case keys and an
`html` field to execute the same checks against native cards. Until that paired
run passes, these browser results cannot be counted as native integration proof.

## Remaining acceptance blockers

* Full own-post/RSS/Bluesky/reply/emoji/facet/quote/media branch coverage is still
  under implementation; partial shared cards cannot replace canonical Library.
* `CardFacts` currently has no complete runtime authoritative resolver for
  CSRF, Ask/poll/local rows, action moderation/admin/ownership facts, emoji and
  mention caches, preview budget and hydrated quote facts. Unit fixtures supply
  these values. Default moderation facts do not establish current settings.
* Rendering must be bound to freshly admitted `AdmittedLibraryPage` content and
  authenticated owner context. An arbitrary `Value` plus manually constructed
  facts should not become a public worker request surface. A module-private
  function is not itself an admission proof.
* Existing PHP action handlers remain necessary. Rendered forms alone do not
  prove current authorization, CSRF rejection, queued failures, idempotency,
  folder persistence, cache invalidation, delete/edit audience effects or
  delivery behavior. Actual controller/action fixtures remain required.
* The complete HTML5 decoder also changes shared Home/notification text, so
  regressions must be checked across the existing renderer suite, not just
  against Library components.
* Production PostgreSQL and cache invalidation checks are separate from this
  fixture-only review. No production accounts were changed or services deployed.
