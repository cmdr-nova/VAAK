# Moderation reports native read (step A7)

Rust paints the report list of the Admin Moderation view (`?view=moderation`): every report card with its label, state, triage priority, handles, comment, referenced posts, private admin notes, the note form, the Inspect / Global mute / Server-wide block controls and the Ignore / Dismiss / Reopen forms. PHP keeps the account moderation card, the filter tabs, the report composer, the nav open-report badge, the shell, CSRF injection and every report and block action.

Admin only, like the PHP view. Default off. It needs `VAAK_ADMIN_READ_NATIVE=1` and `VAAK_ADMIN_READ_SECRET` plus `VAAK_ADMIN_MODERATION_NATIVE=1`, in both `www.conf` and `vaak.env`.

## What it does

`ap_admin_native_read_body('moderation', 0, $modFilter)` posts the usual envelope with `filter` set to one of `open`, `about_us`, `outbound`, `closed`, `all`. The worker requires a current active administrator before and after a READ ONLY transaction, runs the same `ap_reports_list` query for that filter (newest 80 by id), scores each row the way `ap_report_priority_score` does and sorts by priority, then id. PHP now reads `ap_reports_list` only when it paints the list itself.

- Handles follow `actor_handle` with no username hint: the cached actor row and `ap_remote_actor_label`. An uncached or placeholder actor gets the URL-derived handle and the same async actor warm PHP queues.
- "Existing server …" tags follow `admin_global_actor_control`: actor rows of `ap_blocks`, the later row in `ap_block_list` order winning for one value.
- "Admin account" tags follow `admin_is_local_admin_actor`: the page owner's actor plus every `is_admin = 1` account's actor id and key.
- Post links follow `admin_status_href` for `https://` URLs (announce suffix stripped, anything else links to `#`).

The bridge accepts only the closed row shape (`id`, `direction`, `state`, `reporter_actor_id`, `target_actor_id`, `priority_score`, `created_at`), at most 80 rows, checks the request binding including `filter`, then rechecks that the session user is unchanged and still an admin.

Renders the PHP list instead when: a reporter or target is Bluesky-shaped (`did:`, `bsky.app/profile/…`, `/did:plc:…`, which PHP resolves through Bluesky caches) or not `https://`, a local actor has a cached remote_actors row, a referenced post is an AT URI or `bsky:` ref, `status_uris_json` is a JSON object, a created_at the helper can't parse, an unknown filter, a nonzero offset, the account is not a current active admin, or anything else in the bridge refuses.

## Parity check

`api/bin/moderation-native-review.php` (sandbox only) renders the genuine list region with the genuine list, priority, handle, control and admin declarations (request statics reset per case) and compares whitespace-collapsed HTML for every filter in full and shell modes. Cases: empty, and ten reports covering every direction/state pair the template branches on, about-you rows, escaping in comments and notes, `"0"` comments and notes, announce-suffixed, padded and plain-http post URLs, non-string URI entries, 14 URIs (12 shown), invalid JSON, both timestamp formats plus Postgres timestamptz text, a future time, a missing and an empty target, duplicate and trailing-slash block values, a domain block, a Bluesky block row, a disabled admin with a trailing-slash actor, a placeholder-username actor and a bridged handle. It checks PHP's actor warms equal the native queue entries, that the real bridge validator accepts each reply and rejects an extra row key and a different filter binding, and every fallback above plus ordinary account and disabled admin.

2026-10-19: 126/126 checks with INTEGER ids and 126/126 with BIGINT ids (queue Redis on). The Settings accounts (209), Settings lists (111) and Server blocks (60) harnesses still pass.
