# Library canonical hydration: finite implementation contract

Discovery only, 2026-10-11. No implementation, Cargo, activation, or deployment in this phase.

## Actual call chain

`admin_bookmark_network_fragment` in `api/ap-admin.php:5229` obtains raw Rust `/shadow/library-data` rows, then **still calls** `ap_masto_interaction_row_to_status` for every Fedi row. Favourites likewise call `admin_favourite_fedi_page` → `ap_masto_favourites_list` → that mapper. `admin_render_library_entries` then enriches thin statuses and assembles cached quotes in PHP before `/internal/library/render`.

PHP interaction mapping resolves the saved numeric/snowflake SID first (`ap_masto_resolve_status_interaction`), including local, mention, event, legacy/type-8 Announce inner, and type-4 reblog branches. It unwraps boosts, keeps the saved action SID, retries the stripped object URL when empty/thin, supports RSS, and retains an HTTPS link stub on a genuine cache miss. `admin_library_status_enrich` uses cache first then a shared three-fetch signed recovery budget. These are observable membership and action semantics, not just serialization.

Rust currently runs `library_source::hydrate` over those descriptors, rebinds durable Bluesky sources and recursively checks retained authority, then `library_context` admits and paints them. Existing `profile_materialize::project_library_search_source` is exported but has **no invocation anywhere** in the current tree. It can project current local SQL or the latest exact/slash event, but disables local quote attachment and strips event quotes. Wiring it indiscriminately would lose features.

## Five concrete remaining boundaries

1. **Saved-row resolver precedence and omission:** no native equivalent of the complete interaction SID resolver. URL-only lookup can choose a different row from the saved SID and change body, identity, or membership. Native source manufacture must start from the current saved SQL row/window grant.
2. **Canonical local/event normalization:** the profile projector already implements local account identity, body/HTML/entity conversion, media, parent IDs, poll, pins, and dependency journals. The surface wrapper is disconnected. Reply entities with @/# and cached remote reply-parent mapping explicitly fall back. Runtime integration and genuine Library-specific PHP comparisons are absent.
3. **Quotes and private children:** PHP cached quote reconstruction/state and late-painter budget semantics are incomplete natively. Compact previews are not audience grants. The surface projector currently omits quotes; accepted/pending/Ask/private-child rows require the complete PHP fallback until independently ported.
4. **Mixed protocol and missing source recovery:** RSS has current-owner native normalization; raw complete PostView has a native plain branch, but thin/legacy/changed AP-shaped Bluesky snapshots, signed fetch/AppView and canonical source restoration remain fallbacks. Keep FeedView reason/by, labels, CID, facets and nested embeds, not only inner text.
5. **Page contract and effects:** Bookmarks advance by raw selected rows; Favourites hydrate before Bsky filter and slicing. Missing rows/stubs/omissions cannot change offsets. Current owner, saved association, recursive audience/mute/block, display Settings, exact incoming boost SID, link-budget state and guarded writer dependency receipts remain authoritative through final paint.

## Proposed first implementation slice (root acceptance required)

Target **Fedi Bookmarks network pages only**, warm current local rows selected by plain local SID or type-0 local snowflake, whose stored stripped object URL agrees with that exact resolved note. Start with non-quote/non-poll/non-Ask roots, body plus optional local media, and no reply; then separately admit simple local-parent replies only after comparing genuine parent fields. This avoids the Favourites hydration-before-slice complication in the first phase.

Add a private descriptor-only native path bound to `SavedEntryGrant::network`; it resolves the selected raw row independently, constructs canonical status from current SQL using the existing projector, and carries its dependency ledger to final admission/paint. PHP should call this path **before** the interaction mapper for qualifying pages. An all-or-nothing response can return unsupported to the unchanged canonical PHP producer; mixed supported/unsupported batches must not drop an entry. Require actual transport proof that successful qualifying requests make zero PHP interaction/enrichment mapper calls. Replacing descriptors after PHP already mapped them is insufficient.

Do not use `SelectedLibrarySearchSource::library_saved` unchanged as a descriptor-free grant: it presently consumes and validates a normalized source. Extend a private constructor tied to the independently resolved saved SQL source; never deserialize a capability or accept browser-provided URI/visibility as authority. Preserve the original saved SID for undo/boost semantics, plus canonical object/author identities for reply and moderation. Reject conflicting SID-versus-object mapping to PHP rather than silently changing resolver precedence.
